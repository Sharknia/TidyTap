# Finder 잘라내기 설계 및 작업계획

작성일: 2026-09-07

상태: 구현·자동 테스트·핵심 Finder 실검증 완료 / 확장 검증은 검증 기록 참조

## 1. 목표와 확정 범위

Finder에서 `⌘X → ⌘V`는 이동, `⌘C → ⌘V`는 복사로 동작하게 한다.
잘라내기를 눌러도 붙여넣기 전까지 원본 파일은 그대로 둔다.
다른 파일이나 텍스트가 복사·잘라내기되어 클립보드가 교체되면 기존 이동 대기를 취소한다.

이 문서는 기존 MVP의 기능 범위를 확장하는 후속 계획이다.

- 단축키 변환은 Finder의 확인된 파일 목록에서만 수행한다.
- 다른 앱과 Finder의 이름 변경·검색·텍스트 입력은 기존 동작을 유지한다.
- 파일 정보는 Finder 클립보드에 맡긴다. 앱은 다음 붙여넣기를 이동으로 바꿀지와 해당 클립보드 변경 번호만 기억한다.
- 별도 파일 이동 엔진을 만들지 않고 Finder의 기본 복사·이동 명령을 사용한다.
- Windows처럼 사용하는 대상 키는 macOS의 Command 키다. Control 키 재매핑은 하지 않는다.
- 같은 단축키를 처리하는 다른 앱과의 충돌은 사용자 설정에 맡긴다.

제외: Finder 메뉴 변경, 잘라낸 아이콘 반투명 표시, 우클릭 붙여넣기를 이동으로 변경,
다른 파일 관리자, 클립보드 기록 UI, 디스크에 잘라내기 상태 저장, 다른 앱의 키 매핑 자동 변경.
바탕화면은 첫 구현에서 제외하고 Finder 창의 네 가지 보기부터 지원한다.
검색 결과의 파일 목록은 동일한 초점 조건을 통과하고 실제 검증된 경우 지원한다.

## 2. 확인된 근거와 남은 불확실성

[46줄 Swift 실험](../Spikes/FinderFocusProbe/main.swift)과
[실험 기록 및 원본 로그](../Spikes/FinderFocusProbe/README.md)를 기준으로 한다.

macOS 26.5.2에서 관찰한 원본 AXFocusedUIElement:

| 상태 | 원본 역할 및 식별자 | 판별 |
|---|---|---|
| 목록 선택 | AXOutline / ListView | 허용 |
| 아이콘 선택 | AXList / IconView | 허용 |
| 계층 선택 | AXList, 상위 AXBrowser / ColumnView | 허용 |
| 갤러리 선택 | AXList / GalleryView | 허용 |
| 네 보기의 이름 변경 | AXTextField / ShrinkToFit Text Field | 원래 키 전달 |
| 검색창 | AXTextField / AXSearchField 서브역할 | 원래 키 전달 |
| 폴더로 이동 | AXTextField / PathTextField | 원래 키 전달 |

실험은 도구가 Codex를 전면으로 복원하는 특성 때문에 Finder를 직접 지정하는 진단 모드로
수행했다. 초점 분류의 증빙이며 전면 앱 확인과 실제 키 변환을 결합한 검증은 아니다.
제품에서는 진단 모드를 사용하지 않는다.

미검증: 빠른 초점 전환, 이동 명령 전달 후 대기 해제와 Finder 기본 붙여넣기 동작, 반복 붙여넣기,
다른 macOS 버전, Finder의 각종 시트·Quick Look, 실제 Helper의 키보드 권한 조합.
이 항목들은 구현 단계의 통과 조건으로 관리한다. 실험 성공을 배포 완료로 해석하지 않는다.

## 3. 사용자 동작 계약

| 입력 또는 사건 | 기대 동작 |
|---|---|
| 파일 목록에서 ⌘X | Finder 복사를 요청하고 성공을 확인한 후 이동 대기 등록 |
| 일반 ⌘C 또는 변환 대상이 아닌 ⌘X | 입력 관찰 즉시 이동 기억과 보류 V를 무효화하고 원래 키 전달. 복사 실패에도 기억 복원 안 함 |
| 이동 대기에서 파일 목록의 ⌘V | 현재 클립보드 변경 번호가 기억한 번호와 같을 때 Finder 이동 명령을 한 번 전달하고 대기 종료 |
| 이동 대기가 없는 ⌘V | 원래 붙여넣기 |
| 다른 앱·텍스트 입력에서 ⌘X/C/V | 원래 키 전달 |
| 우클릭·메뉴·다른 앱으로 새 복사 | 클립보드 교체를 감지해 이동 대기 말소 |
| 텍스트 붙여넣기만 수행 | 이것만으로 이동 대기를 말소하지 않음 |
| ⌥⌘V 등 추가 보조키 조합 | 기존 동작 유지. 이후 상태는 실제 클립보드 변화로 재검증 |
| Helper 종료·재시작, 기능 끄기 | 메모리 상태 말소. 원본 파일은 그대로 |
| 이름 충돌·권한 부족·디스크 오류 | Finder가 표시하고 처리. 이미 종료한 이동 대기는 복원하지 않음 |
| 이동 명령 전달 후 취소·실패 | 다시 이동하려면 원본에서 ⌘X를 다시 수행. 이후 ⌘V는 Finder 기본 동작 |

붙여넣기 대상은 Finder에서 현재 연 폴더다. 폴더를 선택하기만 해서 그 안으로 붙여넣는
별도 동작은 추가하지 않는다. 파일·폴더 및 다중 선택을 지원 대상으로 한다.

## 4. 구성과 책임

기존 Helper와 단일 CGEventTap을 확장한다. 새 프로세스나 별도 전역 단축키 등록은 만들지 않는다.

| 구성 | 책임 |
|---|---|
| FinderFocusClassifier | 전면 Finder, 현재 초점과 상위 구조를 읽어 files / textOrOther / unknown 분류 |
| FinderCutPasteController | 이동 명령 기억의 등록·덮어쓰기·초기화 및 단축키 변환 결정 |
| FinderPasteboardAdapter | changeCount와 파일 데이터 포함 여부 확인. 파일 URL 목록은 저장하지 않음 |
| CGEventTapBackend | 키 down/up 변환, 반복 입력 및 자체 생성 이벤트 처리 |
| InputFeaturesAdapter / ApplyCoordinator | 설정 적용, 실패·권한·실효 상태 및 롤백 연결 |

앞의 세 구성은 TidyTapInputEngine 내부에 추가한다. 순수 상태 전이와 macOS API 접근은
분리하여 Finder를 실행하지 않고도 경쟁 사건의 순서를 테스트할 수 있게 한다.

### 초점 판정

1. NSWorkspace의 전면 앱이 com.apple.finder인지 확인한다.
2. 현재 AXFocusedUIElement를 읽는다. 실패·없음·알 수 없는 역할이면 통과한다.
3. 목록은 AXOutline/ListView, 아이콘·갤러리는 AXList와 대응 식별자를 확인한다.
4. 계층 보기는 초점 자체가 AXList이며 상위에 AXBrowser/ColumnView가 있는지 확인한다.
5. 다른 역할, 입력창, 메뉴, 시트는 변환하지 않는다. 문자열 내용으로 판정하지 않는다.
6. 처리 직전 앱·창이 바뀌었거나 조회가 불완전하면 변환하지 않는다.

이전 파일 목록 초점을 현재 초점 대신 재사용하지 않는다. 초점 변경 알림은 상태 무효화에
사용할 수 있지만, 알림 미수신을 초점 유지의 증거로 삼지 않는다.
파일 목록 안에 수정 가능한 텍스트 요소가 있다는 이유로 텍스트 입력으로 판정하지 않는다.
파일 선택 유무는 초점과 별개다. ⌘X 후 실제 파일 복사가 확인되어야 대기를 등록한다.

### 키 처리

- 처음에는 추가 Shift/Option/Control이 없는 Command+X/C/V만 대상으로 한다.
- Caps Lock 플래그, 한글·영문 입력 소스에서 같은 단축키가 동작하는지 확인한다.
- down과 up은 한 쌍으로 관리한다. down을 변환했다면 초점이 바뀌어도 대응 up을 정리한다.
- 키 길게 누르기로 복사·이동 요청을 여러 번 만들지 않는다.
- 자체 합성 이벤트를 사용하면 식별 표식을 붙이고 재처리하지 않는다.
- 가능한 경우 원본 X를 C로, V의 보조키를 Option+Command로 바꾸는 경로를 우선 실험한다.
  별도 합성이 필요하면 목표 Finder PID와 현재 창을 확인하고 중복 전송을 방지한다.
- AX 응답 대기와 클립보드 폴링을 이벤트 콜백에서 길게 수행하지 않는다.
  초점 조회는 제한 시간을 두고, 복사 완료 대기는 비동기로 처리한다.
  제품 AX 조회는 전체 30ms 예산, 호출당 최대 5ms로 제한하고 만료 시 통과한다.
  pending 확인은 전용 직렬 큐에서 20ms 간격으로 최대 25회 수행한다. 일반 키마다
  클립보드 IPC를 실행하지 않는다. 이 값은 실제 Finder 추가 검증에 따라 조정할 수 있다.
- 비동기 처리가 필요할 때는 붙잡은 키의 전달 순서와 초점 변경 시 폐기 규칙을 먼저 검증한다.

## 5. 잘라내기 생명주기

파일 목록과 파일 내용은 Finder가 클립보드에 관리한다. TidyTap은 파일 URL 목록을
복제·저장·비교하거나 클립보드 내용을 다시 쓰지 않는다.

명령 기억은 Helper 메모리의 다음 값 하나로 표현한다.

```swift
var cutPasteboardChangeCount: Int? // nil: 일반 붙여넣기, 값 있음: 해당 클립보드는 이동
```

| 상태 | 표현 |
|---|---|
| idle | cutPasteboardChangeCount == nil |
| armed | cutPasteboardChangeCount에 변환한 복사의 변경 번호 저장 |

### 명령 기억 규칙

1. 파일 목록의 유효한 `⌘X`를 `⌘C`로 변환한다. 기존 기억을 지우고, 이번 복사의
   클립보드 갱신을 확인하면 새 변경 번호로 기억을 덮어쓴다.
2. 일반 `⌘C` 또는 변환 대상이 아닌 `⌘X`를 관찰하면 **클립보드 갱신 전에 기억부터 지운다.**
   파일·텍스트 및 앱 구분 없이 적용하되 원래 키는 그대로 전달한다. 우리 앱이 X에서 변환한
   C는 이 초기화 경로에서 제외한다. 복사가 실패하거나 클립보드가 그대로여도 기억을 복구하지 않는다.
   메뉴·우클릭 복사처럼 키 입력으로 관찰하지 못한 경우는 실제 클립보드 변경으로 초기화한다.
3. 기억이 있고 Finder 파일 목록에서 `⌘V`가 발생하면 현재 변경 번호를 비교한다.
   같으면 `⌥⌘V`로 변환하고 기억을 지운다. 다르면 기억을 지우고 원래 키를 전달한다.
4. 다른 앱·텍스트 입력의 붙여넣기는 변환하지 않는다. 붙여넣기 자체는 기억을 지우지 않는다.
5. 새 복사 이후 과거 클립보드를 복원해도 이동 기억은 되살리지 않는다.

예: 파일 A를 잘라낸 뒤 파일 B를 일반 복사하면, 다음 붙여넣기는 B의 일반 복사다.
파일 A의 복사 갱신 확인이 끝난 뒤 파일 B를 다시 잘라내면, 다음 붙여넣기는 B의 이동이다.
확인 중에 누른 추가 파일 X는 아래 규칙에 따라 무시한다.

### 변환한 복사의 갱신 확인

`⌘X`를 `⌘C`로 바꾸는 순간과 Finder가 클립보드를 갱신하는 순간 사이에는 간격이 있다.
이 간격을 처리하기 위한 일시적인 pending 정보는 명령 기억과 별도로 둔다.
파일 작업을 추적하는 지속 상태는 아니다.

- 변환 직전 changeCount, 요청 세대, 당시 Finder 문맥으로 이번 갱신을 기다린다.
  key-down/up 소유 정보도 키 처리에만 사용한다. 파일명·경로는 저장하지 않는다.
- 기존 번호를 즉시 이동 기억으로 등록하지 않는다. 새 파일 데이터가 있는 클립보드
  갱신을 확인한 뒤 그 변경 번호만 저장한다. 파일 형식 확인 전후 번호가 바뀌면 사용하지 않는다.
- 우리 앱이 변환한 복사에 따른 갱신은 기억 등록, 그 외 갱신은 기억 초기화로 처리한다.
  합성 이벤트 표식은 자체 키 이벤트 구분용이며 클립보드 작성 출처의 증명은 아니다.
- **변환한 복사 명령은 한 번에 한 건만 보낸다.** pending 중 추가 파일 ⌘X는 소비하고
  Finder에 보내거나 큐에 쌓지 않는다. 기존 pending을 새 요청으로 교체하지 않는다.
  무시한 X의 key-up·반복 이벤트도 한 쌍으로 정리한다. 완료 후 다시 누른 X는 정상 처리한다.
- pending 중 일반 C 또는 변환 대상이 아닌 X는 즉시 이동 기억·등록 자격·보류 V를 지우고
  원래 키를 전달한다. 앱·창 문맥 변경도 등록 자격과 보류 V를 무효화한다.
  이미 Finder에 보낸 복사를 취소한 것으로 간주하지 않는다.
- 무효화된 pending도 관측 종료 또는 기존 제한 시간까지 전송 슬롯을 유지한다.
  이 구간에 새 파일 X를 보내지 않으며, 늦은 콜백은 요청 세대와 등록 자격을 검사해 버린다.
  제한 시간 이후 늦게 발생한 Finder 갱신의 귀속까지 증명하는 것은 지원 보장이 아니다.
- 유효한 pending 중 빠른 ⌘V는 이전 클립보드에 적용하지 않는다. 같은 파일 문맥에서
  최대 한 건만 보류하고 갱신 확인 후 현재 초점·변경 번호를 다시 검사하여 이동 명령을 보낸다.
  추가 V는 소비한다. pending 무효화·시간 초과·문맥 불일치 시 보류 V는 재생하지 않는다.
- 일반 C로 pending을 무효화한 뒤 새로 누른 V는 원래 동작으로 전달한다.
  일반 복사의 완료를 기다리거나 그 붙여넣기 결과를 보장하지 않는다.
  보장하는 것은 과거 이동 기억으로 V를 이동 명령으로 바꾸지 않는다는 점이다.
- pending의 제한 시간은 유한하게 두고 1단계에서 실측해 정한다. 시간 초과를 복사 성공으로
  간주하지 않는다. 기다리는 동안 이벤트 콜백이나 다른 앱의 입력을 막지 않는다.
- 등록 후에는 클립보드 변경 번호를 주기적으로 확인해 메뉴·우클릭 복사도 반영하고,
  ⌘V 직전 반드시 다시 확인한다. 파일 목록 비교는 하지 않는다.
- Helper 종료·기능 OFF 시 명령 기억과 pending을 모두 지운다.

동시에 외부 프로그램이 클립보드를 덮어쓰는 경우의 완전한 출처 판별은 지원 범위 밖이다.
유효한 pending에서는 변환 후 처음 관측한 안정된 파일 클립보드 갱신을 해당 복사 결과로
취급한다. 복수 갱신·문맥 변경 등 충돌이 관측되면 등록하지 않는다. changeCount나 요청
세대가 클립보드 작성 출처를 증명한다고 가정하지 않는다. 등록 후 관측되는 모든 외부 갱신은
이동 기억을 지운다. 이 제한을 해결하기 위한 파일 목록 저장·별도 이동 엔진은 추가하지 않는다.

### 이동 명령 전달과 대기 종료 — 확정 계약

대기 종료 기준은 **실제 파일 이동 완료가 아니라 Finder에 이동 명령을 한 번 전달한 시점**이다.
`moveRequested`를 지속 상태로 두지 않는다. 이동 완료·진행률·성공 여부를 감시하지 않는다.

| 현재 상태 / 사건 | 처리 | 다음 상태 |
|---|---|---|
| armed / 유효한 파일 목록에서 ⌘V | 기억한 변경 번호와 현재 번호 및 초점을 재검증하고 이동 명령 한 번 전달 | idle |
| armed / 일반 C·변환 대상이 아닌 X 또는 새 클립보드로 교체 | 기록 말소, 현재 키는 해당 문맥의 기본 동작 | idle |
| armed / 텍스트 입력 또는 불명확한 초점 | 원래 키 전달, 클립보드가 그대로면 대기 유지 | armed |
| armed / 전달 전에 명령 생성 실패 | 이동 명령과 일반 붙여넣기를 모두 실행하지 않음 | armed |
| idle / 이전 이동의 성공·실패·사용자 취소 | 대기를 복원하지 않음 | idle |
| idle / 다시 ⌘V | Finder 기본 붙여넣기 | idle |

‘전달’은 변환 이벤트를 반환하거나 전송 API로 명령을 내보내는 것을 뜻한다.
Finder의 수신·실행 완료 확인을 뜻하지 않는다. 명령을 내보낸 뒤에는 결과가 불확실해도
자동 재전송하거나 대기를 복원하지 않는다.

- 명령 전달과 대기 소비는 직렬 처리하여 같은 대기 기록을 두 번 사용하지 않는다.
- 대기 기록을 지워도 변환한 키의 대응 key-up 정리 정보는 유지한다.
  같은 키를 길게 누르는 반복 이벤트로 추가 이동 명령을 만들지 않는다.
- 사용자가 키를 놓고 다시 ⌘V를 누르면 기본 동작으로 전달한다.
  Finder의 파일 작업이 진행 중이라는 이유로 새 키를 차단하지 않는다.
- 이동을 취소하거나 실패해도 대기는 끝난다. 다시 이동하려면 남은 원본을 선택해
  ⌘X를 다시 수행해야 한다. 다중 파일 일부 성공도 같은 규칙이다.
- 다음 기본 붙여넣기의 결과는 당시 Finder와 클립보드 상태에 따른다.
  TidyTap이 과거 파일 목록을 클립보드에 복원하거나 별도 이동 명령으로 바꾸지 않는다.
- 전송 전 실패와 전송 후 Finder 작업 실패를 구분한다. 전송 전 실패로 armed를
  유지하는 경우에도 다음 입력에서 클립보드·초점을 다시 확인한다.

이 계약은 실패 후 이동 대기를 자동 유지하는 Windows식 재시도 동작까지 보장하지 않는다.
대신 실제 이동 결과를 추측하는 타이머나 별도 파일 이동 엔진을 사용하지 않는다.

## 6. 설정·권한·기존 기능 연결

- 설정: finderCutPasteEnabled: Bool, 기본 false. 이전 저장값에 키가 없으면 false로 읽는다.
- requiresHelper와 기능 열거형, 실효 설정, 적용 결과 및 롤백에 새 기능을 포함한다.
- 설정 UI는 ‘Finder에서 잘라내기 사용’ 토글과 ‘⌘X로 잘라내고 ⌘V로 이동’ 설명을 추가한다.
  한/영 문자열, 키보드 탐색, 접근성 이름을 기존 설정 UI 체계에 맞춘다.
- pending/실패는 기존 applyRequestID 기반 응답으로 표시한다. 저장만 성공한 상태를
  기능 활성화 성공으로 표시하지 않는다.
- 기존 권한 주체와 Helper 실행 구조를 유지한다. 실제 서명 앱에서 키보드 event tap과
  AX 조회에 필요한 권한 조합을 확인하고 요구 권한 집합·안내 문구를 맞춘다.
- 권한 회수·Secure Input·tap 비활성화·재설치 시 오래된 키 소유권과 작업을 무효화한다.
  단순 휠 설정 변경에 따른 tap 재설치는 armed 상태를 보존할 수 있으나 클립보드를 재검증한다.
  비동기 복사·이동 요청은 설정 세대가 바뀌면 그대로 재실행하지 않는다.
- Finder 기능만 실패할 때 기존 휠·측면 버튼·Caps Lock을 불필요하게 끄지 않는다.

## 8. 필수 검증 시나리오

순수 로직 테스트:
- 다른 앱, 텍스트 초점, AX 오류, 모르는 식별자는 변환하지 않음.
- 새 파일 클립보드 확인 전에는 armed가 되지 않음.
- 요청 세대가 붙은 내부 콜백과 유효한 관측 기간 안에서, 새 복사 뒤 오래된 콜백이 이동 기억을 부활시키지 않음. 제한 시간 이후 Finder 갱신의 귀속 보장과 구분.
- 일반 파일 C·텍스트 복사·클립보드 기록 복원은 기억 초기화. 같은 파일도 새 번호면 초기화.
- pending 중 추가 파일 X는 전송하지 않음. 완료 후 새 X만 기억 덮어쓰기.
- armed에서 일반 C 직후 클립보드가 아직 이전 번호여도 V를 이동으로 바꾸지 않음.
- 일반 C 실패에도 기억 복원 없음. 자체 변환 C는 자기 pending을 취소하지 않음.
- pending 중 C → 늦은 갱신/콜백은 armed를 부활시키거나 보류 V를 실행하지 않음.
- 무효화된 pending의 전송 슬롯, 시간 초과, 보류 V 최대 한 건, key-up 정리 검증.
- down/up 사이 초점 변경, 키 반복, 자체 합성 이벤트가 중복 명령을 만들지 않음.
- 이동 명령을 한 번 전달하면 즉시 idle. Finder 성공·실패·취소로 armed가 복원되지 않음.
- 전송 전 실패는 대기를 유지하되 일반 붙여넣기로 바꾸지 않음. key-up과 반복 입력 정리 검증.

실제 Finder 검사(기존 파일 대신 임시 파일 사용):
- 네 보기에서 단일·다중 파일·폴더: X→V 이동 및 C→V 복사.
- 각 보기의 이름 변경에서 X/C/V로 텍스트 편집 정상. 원본 파일 이동 없음.
- 검색창, 폴더 이동 창, 태그 입력, Quick Look, 시트, 사이드바에서 오개입 없음.
- Return 직후 X, Escape 직후 X, X 직후 V, 도중 앱·창·탭 전환.
- 파일 A의 X 완료 → 파일 B의 C → 즉시 V: TidyTap이 이동 명령을 만들지 않음.
- 파일 A의 X 완료 → 파일 B의 X 완료 → V는 B 이동.
- X 갱신 확인 중 X 연타는 복사 한 건만 전송. X → 빠른 V는 최대 한 번 이동.
- X pending → 일반 C → V 및 X pending → C → 늦은 갱신에서 과거 이동 기억 부활 없음.
- 다른 앱·우클릭·메뉴의 파일/텍스트 복사 후 V는 새 클립보드의 기본 붙여넣기.
- 같은 폴더, 이름 충돌 취소, 읽기 전용 대상, 다른 볼륨, 이동 도중 대상 연결 해제.
- 명령 전달 직후 및 이동 완료 후 새 V는 기본 동작. 실패·취소 후에도 대기 없음.
- 실패·취소·다중 파일 일부 성공 후 남은 원본에서 X를 다시 수행해 이동 재시도.
- 한글/영문 입력, Caps Lock 켬, 추가 보조키, 길게 누르기.
- 접근성 권한 회수·복원, Secure Input, Helper 재시작, 기능 OFF.
- 휠 방향·고정 단계·측면 버튼·Caps Lock 기능과 함께 사용.

검증 결과는 `docs/FINDER_CUT_PASTE_VALIDATION.md`에 OS/빌드·실제 관찰·통과/실패·
미검증을 구분해 기록한다. 성능은 입력 시점부터 전달까지 지연을 측정하고 AX 지연으로
tap timeout이나 기존 휠 입력 지연이 발생하지 않는지 확인한다.

완료 기준: 실제 파일 이동·복사 결과와 텍스트 편집 보존을 확인하고, 위 필수 시나리오의
실패 또는 미검증 항목을 숨기지 않는다. 단위 테스트 성공만으로 기능 완료를 선언하지 않는다.
