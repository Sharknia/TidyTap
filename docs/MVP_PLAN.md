# TidyTap MVP 작업 계획서

상태: 범위 고정  
대상 릴리스: `0.0.1`
작성일: 2026-09-04

## 1. 제품 목표

TidyTap은 macOS의 세 가지 입력 불편만 해결하는 작은 유틸리티다.

1. Caps Lock을 대문자 고정 없이 입력 소스 전환 전용 키로 사용한다.
2. 트랙패드 방향은 유지하면서 지원하는 외장 마우스의 수직 휠 방향만 반전한다.
3. Safari와 Finder에서 지원하는 외장 마우스 측면 버튼으로 뒤로/앞으로 이동한다.

이 문서에 명시되지 않은 기능은 MVP에 포함하지 않는다. 새 기능 제안은 `0.0.1` 완료 후 별도 이슈로만 기록하며, 현재 구현에 끼워 넣지 않는다. 범위 고정 이후 변경은 기존 인수 기준을 달성하지 못하게 하는 차단 문제를 수정할 때만 허용한다. 그 밖의 변경은 이후 릴리스로 미룬다.

## 2. 지원 범위

- 지원 및 검증 Mac: MacBook Pro `Mac15,6` (Apple M3 Pro)
- 지원 및 검증 운영체제: macOS 26.6.2 (`25G83`)
- 지원 및 검증 마우스: VXE Mouse 1K Dongle
- 검증 트랙패드:
  - MacBook 내장 트랙패드
  - Apple Magic Trackpad
- 입력 소스 전제: 활성 입력 소스가 정확히 2개인 환경
- UI 언어: 한국어, 영어
- 배포 방식: GitHub Releases를 통한 직접 배포
- 앱 형태: 실행 중 Dock에 나타나는 일반 macOS 설정 앱

다른 Apple Silicon 모델, Intel Mac, macOS 26.6.2 이외 버전, Mac App Store 배포는 MVP 지원 범위가 아니다. 다른 환경에서 실행될 수는 있지만 `0.0.1`에서 호환성을 주장하지 않는다.

## 3. MVP 기능 계약

### 3.1 Caps Lock 입력 소스 전환

- 사용자가 기능을 켜면 Caps Lock HID usage를 F18로 매핑한다.
- macOS의 "이전 입력 소스 선택" 단축키를 F18로 설정한다.
- 한 번 누를 때 입력 소스를 정확히 한 번 전환한다.
- 길게 눌러도 Caps Lock 상태, 대문자 고정, 반복 전환이 발생하지 않는다.
- 사용자의 기존 HID 매핑과 입력 소스 단축키를 백업한다.
- Caps Lock에 이미 다른 HID 매핑이 있으면 덮어쓰지 않고 기능 활성화를 거부한다.
- 활성화할 때 기존 매핑 배열에 Caps Lock→F18 항목만 추가하며 다른 항목을 보존한다.
- 기능을 끌 때 현재 매핑 배열에서 정확히 Caps Lock→F18 항목만 제거하고 다른 항목을 보존한다.
- 입력 소스 단축키는 현재 값이 TidyTap이 설정한 F18 값과 동일한 경우에만 백업값으로 복원한다. 활성화 이후 사용자가 단축키를 바꿨다면 새 값을 덮어쓰지 않고 충돌 상태를 표시한다.
- 입력 소스의 추가, 제거, 순서 변경 UI는 제공하지 않는다.
- 활성 입력 소스가 1개 또는 3개 이상이면 기능 활성화를 거부하고 정확히 2개가 필요하다고 표시한다.

### 3.2 마우스 수직 휠 반전

- VXE Mouse 1K Dongle의 수직 스크롤 이벤트만 반전한다.
- 내장 트랙패드와 Magic Trackpad의 스크롤 방향 및 제스처는 변경하지 않는다.
- 수평 스크롤은 변경하지 않는다.
- 스크롤 속도, 가속, 단계 크기는 변경하지 않는다.
- 기능을 끄면 이벤트 탭에서 스크롤 이벤트를 즉시 통과시킨다.

장치 구분은 다음 최소 규칙으로 구현한다.

1. 비연속 line-based 스크롤은 마우스로 분류한다.
2. 최근 다중 터치 제스처와 연결된 연속 스크롤 및 모멘텀은 트랙패드로 분류한다.
3. 그 밖의 연속 스크롤은 알 수 없는 장치로 분류하고 변경하지 않는다.

UI 구현 전에 세 검증 장치로 이 분류 규칙을 먼저 실험한다. VXE는 양방향 휠 이벤트 100개 이상, 각 트랙패드는 세로·가로·모멘텀을 포함한 이벤트 200개 이상을 관찰한다. 트랙패드 이벤트가 한 번이라도 마우스로 분류되거나 VXE 이벤트가 한 번이라도 트랙패드/unknown으로 분류되면 실패다. 분류 규칙이 입력 장치의 직전 상태에 의존하지 않으므로 별도의 장치 교대 반복 시험은 하지 않는다. 실패하면 구현을 확장하지 않고 작업을 중단하여 범위와 기술 방식을 다시 승인받는다.

### 3.3 Safari 및 Finder 측면 버튼 탐색

- Core Graphics 기준 측면 버튼 3을 뒤로, 버튼 4를 앞으로 처리한다.
- 앞면 앱이 Safari 또는 Finder일 때만 각각 `Command-[`, `Command-]`를 보낸다.
- Safari와 Finder는 하나의 기능 토글로 함께 켜고 끈다.
- Safari와 Finder에서는 button-down에 탐색을 한 번 보내고 해당 button-down/up을 모두 소비한다. 키를 누르고 있어도 button-up 전에는 다시 보내지 않는다.
- 다른 앱에서는 원래 button-down/up을 모두 수정하지 않고 통과시킨다.
- 비활성 또는 포커스가 없는 Safari/Finder 창을 탐색하지 않는다.
- 사용자 지정 버튼 매핑은 제공하지 않는다.

구현 전에 VXE 마우스가 측면 버튼을 Core Graphics 버튼 3/4로 보고하는지 확인한다. 반대로 보고되는 경우에만 코드 상수의 방향을 바로잡고, 사용자용 보정 UI는 추가하지 않는다.

### 3.4 필수 앱 동작

- `로그인할 때 시작`
  - 켜면 백그라운드 helper를 로그인 항목으로 등록한다.
  - 끄면 다음 로그인부터 자동 시작하지 않는다. 현재 세션의 활성 기능은 유지한다.
`로그인할 때 시작`은 사용자가 선택할 수 있는 설정이지만 구현 및 검증 범위에서는 필수 MVP 기능이다.

## 4. UI 범위

설정 앱은 창 하나만 제공한다.

```text
TidyTap

[ ] Caps Lock으로 입력 소스 전환
[ ] 마우스 휠 수직 방향 반전
[ ] Safari와 Finder에서 측면 버튼으로 뒤로/앞으로

옵션
[ ] 로그인할 때 시작
버전 0.0.1
zel@kakao.com
github.com/Sharknia/TidyTap
```

- 버전은 앱 번들에서 읽는다.
- 이메일과 GitHub 주소는 클릭 가능한 링크다.
- 권한이 없을 때만 같은 창 안에 권한 설명과 시스템 설정 열기 버튼을 표시한다.
- 별도 온보딩, 튜토리얼, 설정 탭, 진단 화면은 만들지 않는다.

## 5. 프로세스 구조와 생명주기

### TidyTap.app

- AppKit으로 작성한 일반 Dock 앱이다.
- 설정을 표시하고 변경한다.
- `Command-Q`로 종료하면 설정 앱 프로세스만 종료한다.

### TidyTapHelper

- Dock에 나타나지 않는 단일 백그라운드 helper다.
- Caps Lock 매핑 재적용과 마우스 이벤트 탭을 담당한다.
- 설정 앱이 종료되어도 활성화된 마우스 기능을 유지한다.
- 핵심 기능 중 하나가 켜져 있는 동안 실행된다.
- 모든 핵심 기능이 꺼지면 이벤트 탭을 제거하고 종료한다.
- 별도의 기능별 daemon이나 시스템 확장은 만들지 않는다.

설정은 사용자 Library의 단일 preferences domain에 저장한다. 설정 앱은 값을 저장한 뒤 `DistributedNotificationCenter`로 helper에 변경을 알린다. helper는 알림 수신 후 1초 안에 전체 설정을 다시 읽고 적용하며, 시작할 때도 전체 설정을 읽는다.

- `로그인할 때 시작`이 켜져 있으면 ServiceManagement가 로그인 직후 helper를 실행하며 모든 저장 설정을 복원한다.
- 이 설정이 꺼져 있으면 재부팅 후 자동으로 기능을 적용하지 않는다. 사용자가 TidyTap.app을 열면 helper를 시작해 저장 설정을 적용한다.
- helper 프로세스 자체의 충돌 자동 재시작은 MVP 범위가 아니다. 이벤트 탭이 macOS에 의해 비활성화된 경우에는 콜백에서 다시 활성화한다. helper가 종료되면 사용자가 TidyTap.app을 다시 열어 복구한다.

## 6. 권한과 개인정보 보호

- Caps Lock 기능만 사용할 때는 접근성 또는 입력 모니터링 권한을 요구하지 않는다.
- 휠 반전 또는 측면 버튼 기능에는 접근성 권한이 필요하다.
- 트랙패드 제스처를 관찰하는 event tap에는 입력 모니터링 권한이 필요하다.
- 권한이 거부되면 해당 기능을 켜진 것처럼 표시하지 않고 이유를 보여준다.
- 네트워크 요청, 텔레메트리, 키 입력 기록, 마우스 좌표 기록을 하지 않는다.
- 이벤트 콜백에서는 필요한 이벤트 종류와 버튼/스크롤 값만 즉시 처리하고 저장하지 않는다.

## 7. 기존 도구에서의 전환

개발 및 검증 시 다음 충돌을 수동으로 제거한다.

- 현재 개인용 Caps Lock LaunchAgent는 TidyTap의 Caps Lock 기능을 검증한 뒤 제거한다.
- Scroll Reverser는 TidyTap의 휠 기능을 검증하기 전에 종료하고 로그인 항목에서 해제한다.
- TidyTap 자체가 타사 앱을 종료하거나 제거하지 않는다.

지원하는 제거 절차는 다음으로 고정한다.

1. TidyTap에서 세 핵심 기능과 로그인 실행을 모두 끈다.
2. Caps Lock 백업 복원 완료와 helper 종료 상태를 확인한다.
3. TidyTap.app을 종료하고 삭제한다.

활성 기능이 남은 상태에서 Finder로 앱을 바로 삭제하는 경우 자동 복원은 지원하지 않는다. 별도 uninstaller는 만들지 않으며 README에 위 절차를 명시한다.

## 9. 구현 순서와 중단 조건

물리 입력이 필요한 검증은 자동으로 시작하지 않는다. 실행 전에 시험할 장치, 사용자가 수행할 동작과 횟수, 제한 시간, 일시 중단할 기존 앱을 먼저 안내하고 사용자의 명시적인 시작 확인을 받는다. 안내하지 않은 입력이나 다른 장치 입력이 섞이면 해당 실행 결과 전체를 무효 처리한다. 시험이 끝나면 일시 중단한 앱을 원래 상태로 복구한다.

### 단계 0: 기술 검증

1. Caps Lock→F18 매핑, 입력 단축키 변경, 길게 누르기, 백업, 조건부 복원을 확인한다.
2. `/usr/bin/hidutil`, `/usr/bin/defaults`, `/System/Library/PrivateFrameworks/SystemAdministration.framework/Resources/activateSettings -u`가 macOS 26.6.2에서 관리자 및 접근성 권한 없이 동작하는지 확인한다. 마지막 내부 시스템 명령은 Caps Lock 단축키 갱신에만 허용하며 사용할 수 없으면 단계 0 실패로 처리한다.
3. VXE 휠과 두 트랙패드의 이벤트 특성을 저장하지 않는 진단 빌드로 정량 검증한다.
4. 접근성 및 입력 모니터링 권한을 각각 거부, 허용, 허용 후 회수한 상태에서 실패 동작을 확인한다.
5. VXE 측면 버튼 번호와 Safari/Finder 단축키 동작을 확인한다.
6. `TidyTap.app` 종료 후 별도 helper가 유지되고 설정 변경 알림을 1초 안에 적용하는지 확인한다.

다음 중 하나라도 실패하면 UI 구현을 시작하지 않는다.

- 마우스 휠과 트랙패드를 안정적으로 구분할 수 없음
- private API 없이 Safari/Finder 탐색을 구현할 수 없음
- helper가 설정 앱과 독립적으로 안정적으로 실행되지 않음
- Caps Lock 설정 변경 및 조건부 복원이 macOS 26.6.2에서 검증되지 않음

### 단계 1: 프로젝트 골격

1. Xcode 프로젝트와 AppKit 설정 앱 target을 만든다.
2. 단일 background helper target과 ServiceManagement 등록을 구성한다.
3. 공용 설정 모델과 한국어/영어 String Catalog를 만든다.

### 단계 2: Caps Lock 기능

1. 기존 HID 매핑과 입력 소스 단축키의 백업/복원을 구현한다.
2. Caps Lock→F18 적용과 토글을 구현한다.
3. 길게 누르기, 반복 입력, helper 재시작, 로그인 재적용을 검증한다.

### 단계 3: 마우스 이벤트 기능

1. 단일 `CGEventTap`과 권한 처리를 구현한다.
2. 수직 휠 반전과 트랙패드 통과를 구현한다.
3. Safari/Finder 측면 버튼 탐색과 다른 앱 통과를 구현한다.
4. 이벤트 탭 비활성화/재활성화와 helper 재시작을 검증한다.

### 단계 4: 최소 UI와 생명주기

1. 세 기능 토글, 로그인 옵션, 권한 상태, 하단 정보를 연결한다.
2. Dock 앱 종료 후 helper 유지 동작을 검증한다.
3. 모든 기능 비활성화 시 입력 이벤트를 가로채지 않는지 검증한다.

### 단계 5: 배포 준비

1. 기존 도구에서 전환 및 완전 복원 절차를 문서화한다.
2. Release 구성을 빌드하고 MacBook Pro `Mac15,6`/macOS 26.6.2에서 전체 인수 테스트를 수행한다.
3. Developer ID로 서명하고 Apple 공증을 거친 DMG를 만든다.
4. GitHub Release `0.0.1`과 체크섬을 게시한다.

Developer ID 자격 증명이 준비되지 않으면 서명되지 않은 개발 빌드까지만 만들고, `0.0.1` 공개 릴리스는 완료로 표시하지 않는다.

## 10. 인수 기준

### 전체

- 세 기능은 서로 독립적으로 켜고 끌 수 있으며 재실행 후 상태가 유지된다.
- 기능을 끈 뒤 1초 이내 또는 다음 입력 이벤트 전까지 해당 동작이 macOS 기본값으로 돌아간다.
- 설정 앱을 `Command-Q`로 종료해도 켜진 마우스 기능은 유지된다.
- 모든 기능을 끄면 실행 중인 이벤트 탭이 없다.
- helper가 비정상 종료되어도 고정된 modifier나 mouse-down 상태를 남기지 않는다. 자동 재시작은 요구하지 않는다.
- 설정 앱과 helper가 함께 실행 중일 때 모든 토글 변경이 1초 안에 helper에 반영된다.

### Caps Lock

- macOS 키 반복을 현재값과 시스템 설정에서 선택 가능한 가장 빠른 값으로 각각 설정해 시험한다.
- 각 키 반복 설정에서 50~150ms 누름을 25회 수행하고, 누름마다 입력 소스가 정확히 한 번 전환된다.
- 각 키 반복 설정에서 2초 누름을 5회 수행하고, 누름마다 입력 소스가 정확히 한 번만 전환되며 Caps Lock 상태와 LED가 켜지지 않는다.
- 비활성화할 때 HID 배열에서는 TidyTap의 정확한 Caps Lock→F18 항목만 제거하고 나머지 매핑을 보존한다.
- 현재 입력 소스 단축키가 TidyTap의 F18 값이면 백업값으로 복원한다.
- 활성화 이후 외부에서 HID 매핑 또는 F18 단축키를 변경하면 TidyTap은 그 값을 덮어쓰지 않는다.
- 외부 변경 때문에 단축키를 복원하지 않은 경우 충돌 상태를 표시하면 인수 기준을 통과한 것으로 본다.
- Caps 기능만 켠 깨끗한 사용자 계정에서 접근성 및 입력 모니터링 권한 요청이 나타나지 않는다.

### 스크롤

- VXE 마우스의 양방향 휠 이벤트 100개 이상이 모두 반전 대상으로 분류된다.
- 내장 트랙패드와 Magic Trackpad의 수직·수평 스크롤과 모멘텀이 바뀌지 않는다.
- 각 트랙패드에서 세로·가로·모멘텀을 포함한 이벤트 200개 이상을 관찰하고 마우스 오분류가 0회다.
- TidyTap과 Scroll Reverser를 동시에 실행하지 않은 상태에서 검증한다.
- 접근성/입력 모니터링을 거부하거나 회수하면 기능을 비활성 상태로 표시하고 원본 이벤트를 변경하지 않는다. 이후 권한을 허용하면 앱 재설치 없이 활성화할 수 있다.

### 측면 버튼

- Safari와 Finder의 활성 창에서 뒤로/앞으로가 정확히 한 번 실행된다.
- 각 앱에서 각 버튼을 짧게 20회, 2초간 길게 5회 눌러 누름당 탐색이 정확히 한 번 발생한다.
- 방문 기록이 없을 때 오류나 다른 동작이 발생하지 않는다.
- 다른 앱에서는 합성된 탐색 입력을 보내지 않는다.
- Safari/Finder에서는 원본 down/up을 소비하고, 다른 앱에서는 동일 이벤트를 그대로 통과시킨다.

### 옵션과 배포

- 로그인 실행을 켜면 재부팅 후 helper가 기능을 복원한다.
- 로그인 실행을 끄면 다음 로그인에 helper가 자동 시작하지 않는다.
- 공증된 DMG가 MacBook Pro `Mac15,6`의 깨끗한 macOS 26.6.2 사용자 계정에서 설치되고 Gatekeeper 경고 없이 실행된다.
- 깨끗한 계정의 한국어 및 영어 시스템 언어에서 모든 문자열이 해당 언어로 표시되고 잘리거나 하드코딩된 반대 언어 문구가 없다.
- 깨끗한 계정에서 권한 안내, 세 기능, `Command-Q` 이후 helper 유지, 로그인 재적용, 비활성화와 제거 전 복원을 처음부터 끝까지 통과한다.

## 11. 완료 정의

아래 조건을 모두 만족할 때만 MVP를 완료로 본다.

1. 단계 0에 나열한 여섯 기술 검증을 모두 통과한다.
2. 모든 인수 기준을 실제 대상 장치에서 통과한다.
3. 모든 기능을 비활성화한 뒤 앱을 삭제하는 지원 제거 절차에서 기존 시스템 설정이 복원된다.
4. README에 설치, 권한, 제거, 알려진 제한을 기록한다.
5. 코드에 네트워크, 텔레메트리, 범위 밖 설정이 포함되지 않는다.
6. Developer ID 서명과 Apple 공증을 통과한 `0.0.1` DMG를 GitHub Release에 게시한다.

기존 인수 기준을 달성하지 못하게 하는 차단 문제가 발견된 경우에만 이 문서를 먼저 수정하고 별도의 커밋으로 변경 이유를 남긴다. 기능 추가나 지원 범위 확대는 `0.0.1` 문서를 변경하지 않고 이후 릴리스 이슈로 미룬다.
