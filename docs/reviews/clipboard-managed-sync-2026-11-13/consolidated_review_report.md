# TidyTap 0.3.0 동기화 계획 금붕어 검토 결과

주인님, **Core Data 우선 검증을 위한 조사·시험 설계부터 시작할 수 있다.** OFF 일시중지·ON 병합과 목표 제품 버전 0.3.0을 계획서에 반영했다. 전체 제품 구현은 Core Data 적합성 검증과 Gate1 상세 설계 뒤에 진행한다. 이번 검토는 동기화 구현이나 실기기 시험의 완료 판정이 아니다.

## 반영한 범위

OFF에서도 로컬 수집·고정·삭제를 유지하고 새 클라우드 송수신을 중지한다. ON은 같은 계정의 유효한 로컬 변경과 원격 변경을 조정한다. 삭제·만료를 단순 목록 합집합으로 복원하지 않는다. 설정 의도·끄는 중·꺼짐 완료를 구분하고, 이미 서버가 받은 작업을 취소로 되돌린다고 약속하지 않는다.

우선 후보는 Core Data와 NSPersistentCloudKitContainer다. 격리 probe에서 같은 store/history를 유지하는 OFF/ON·삭제·두 프로세스 접근을 먼저 검증한다. 실패 근거가 있으면 파일+CKSyncEngine 대안을 다시 비교한다. 두 전송 엔진을 동시에 붙이지 않는다.

보관함 1개, 일반 히스토리 동기화, 항상 최근 기록으로 열기, 최근 기록/보관함 탭과 패널 안의 ⌘1/⌘2는 유지한다. 목표 제품 버전은 0.3.0이고 문서 개정 번호는 0.5다. 프로젝트 버전 설정이나 빌드는 변경하지 않았다.

창 닫기 때 미러링 유지, 명시적 ⌘Q 뒤 다음 실행에서 재개하는 수명은 **기준안**이다. 사용자 확정과 구분하며 Gate0-A에서 시험 요구로 잠근다.

## 검증 범위와 한계

기록된 문서 해시·행 범위·로컬 링크·M01~15 식별자·공백 오류를 확인했다. 제품 소스·실제 저장 데이터·계정·클라우드 자원은 변경하지 않았다. 빌드·제품 시험·실제 iCloud 송수신은 실행하지 않았다.

검토자는 persona·기준·지정 맥락을 읽었다고 각각 보고했다. 부모에게 개별 자식 도구 기록은 노출되지 않아 이 완료 보고를 별도로 검증하지는 못했다. `fork_turns: none`은 부모 대화를 제외하지만 host의 지침 파일 주입까지 배제한다는 증거는 없다. 지정 UI 문서에는 과거 검토 상태 설명이 남아 있으나 과거 보고서 본문은 공급하지 않았고, 8단계에서만 이번 실행의 선행 보고서를 읽었다.

Core Data의 실제 OFF/ON 적합성, 오래된 삭제의 재등장 방지, 계정 분리·용량·프로세스 수명은 예정 시험 전까지 미확인이다. 마지막 W01 표현 수정은 추가 독립 검토하지 않았다.
