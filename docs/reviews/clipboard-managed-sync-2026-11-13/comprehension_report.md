## What this proposes

주인님, 이 문서는 최근 클립보드 기록과 고정 보관 항목을 같은 Apple 계정의 Mac 사이에서 동기화하는 계획입니다. OFF에서도 로컬 기록과 변경을 유지하고, 다시 ON하면 삭제 이력까지 반영해 원격 기록과 병합합니다. 먼저 Core Data·CloudKit 관리형 동기화의 적합성을 격리된 probe로 검증하고, 제품 모델과 정책을 확정한 뒤 저장소·UI·동기화를 구현합니다.

## How the existing system works, per this document

현재 제품은 `.clip` 직렬화 파일을 사용하는 로컬 저장 방식이며, 일반 기록에는 7일·1,000개·총 50MiB·항목당 10MiB 제한이 있습니다. 복사 또는 붙여넣기 시도를 시작하면 최근 사용 시각을 갱신하고, 본문과 지원 서식이 같은 항목은 최신 한 건으로 표시합니다. 입력 Helper는 독립 실행 파일이며, 기존 입력 설정 저장에는 snapshot·request ID·적용 상태가 관여하므로 새 동기화 설정은 별도 경로로 저장하려 합니다.

**C01 — EGM Major / 사용자 중간**

- **위치:** 124행 M04, 137행, 143행.
- **근거:** M04의 기대 결과가 “옛 항목 재생성 관찰”로 적혀 있습니다. 삭제된 옛 항목의 재생성을 요구하는 것인지, 재생성 여부를 관찰하라는 뜻인지 구분되지 않습니다. 다른 절의 삭제 부활 금지 약속과 연결하면 후자로 읽히지만, 시험 표 자체에서는 재생성을 발견했을 때의 판정이 불명확합니다.
- **최소 개선:** “옛 항목 재생성 여부 관찰. 재생성 시 실패. 해당 중단 경계를 재현하지 못하면 미실행”처럼 관찰 대상과 판정을 나눠 적습니다.
- **등급 근거:** 현재는 계획 단계이므로 제품 장애를 뜻하지 않습니다. 다만 Gate0 시험 전에 판정 문구를 바로잡아야 합니다.

**C02 — EGM Major / 사용자 중간**

- **위치:** 67행, 132행 M12, 143행.
- **근거:** 주앱 종료·⌘Q·로그인 뒤에도 “정한 동기화 수명”을 유지해야 한다고 하지만, 그 수명이 무엇인지 문서 안에 정의되어 있지 않습니다. M12의 “이후 반영”도 주앱이 종료된 동안 반영되어야 하는지, 다음 실행 때 반영되어도 되는지를 구분하지 않습니다. 따라서 독자는 어떤 실행 주체가 요구를 충족하는지 판단할 기준을 재구성할 수 없습니다.
- **최소 개선:** 창 닫기·⌘Q·로그인 각각에 대해 수집과 미러링의 계속 실행 여부, 중단을 허용한다면 재개 계기를 짧은 표로 명시합니다. 아직 미정이라면 Gate0에서 기술 가능성을 판단하기 전에 확정할 요구사항으로 표시합니다.
- **등급 근거:** 실행 주체를 조사하는 작업 자체는 이미 계획에 있습니다. 지적 대상은 조사 결과를 판정할 사용자 동작 기준의 누락이며, 현재 제품 영향은 없습니다.

읽은 파일: 지정된 `agents/comprehension.md`와 `docs/CLIPBOARD_PINBOARD_ICLOUD_PLAN.md` 전체 1~157행. Comprehension 검토를 완료했습니다.

외부 문서·소스코드·메모리 조회, 파일 수정, 제품 시험은 하지 않았습니다. 두 지적은 문서의 해석·판정 기준에 관한 것으로 실제 프레임워크 결함을 확인한 결과가 아닙니다.
