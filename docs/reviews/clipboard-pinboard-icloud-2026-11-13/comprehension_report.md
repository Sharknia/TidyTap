## What this proposes

주인님, 이 계획은 기존 macOS 클립보드 히스토리에 여러 항목을 담는 고정 보관함 하나를 추가하고, 일반 히스토리와 고정 상태를 같은 Apple 계정의 Mac끼리 동기화하자는 제안입니다. 로컬 사용을 유지하면서 CloudKit 개인 데이터베이스를 연결하고, 오프라인 변경·삭제·만료·계정 전환을 처리합니다. 저장 정책과 실행 프로세스를 먼저 확정한 뒤 구현과 두 Mac 수용 검증을 진행하며, 실제 구현이나 공개 배포가 완료되었다는 뜻은 아닙니다.

## How the existing system works, per this document

현재 저장소는 복사마다 UUID를 만들고 시각과 본문을 파일에 저장하며, 앱과 Helper가 같은 디렉터리 잠금을 사용합니다. 일반 기록은 만료·중복·용량에 따라 정리되고, 기존 검색·필터·미리보기·서식 선택·붙여넣기 경로가 있습니다. Helper는 앱에 포함된 독립 실행 파일이며, 설정 창이나 앱을 닫은 뒤에도 켜진 기능을 유지하는 흐름이 있습니다. 문서는 기존 시스템을 로컬 전용으로 설명하지만, 구체적인 기존 UI나 제외 표식의 규격까지 설명하지는 않습니다.

### C01: 고정 보관함에서 실행하는 삭제의 범위

- EGM 등급: Major
- 사용자 등급: 중간
- 대상 행: 41~43, 79~80, 109~111
- 이해가 갈리는 이유: 일반 히스토리에서 삭제하면 고정 항목을 보존한다는 규칙과 고정 해제의 동작은 명확합니다. 그러나 41행이 언급하는 고정 항목의 삭제가 고정 상태만 제거하는지, 일반 히스토리에서도 제거하는지 설명하지 않습니다. 따라서 독자는 같은 항목이 두 목록에 있을 때 고정 보관함에서 삭제한 결과를 서로 다르게 이해할 수 있습니다.
- 보완: 고정 해제와 고정 항목 삭제의 차이, 삭제 후 일반 히스토리 잔존 여부와 다른 Mac 반영 범위를 정책 표에 명시하십시오. 아직 결정하지 않았다면 고정 항목 삭제 의미를 1단계의 미정 정책으로 명시하고 해당 수용 기준에 연결하면 됩니다. 구현 전이며 실제 사용자 데이터가 없으므로 현재 작업의 차단 사유로 보지는 않습니다.

엔진 실행 주체, 항목 식별·중복 정책, 고정 한도와 계정 전환 시 표시 방식은 후속 단계의 결정 대상으로 명시되어 있어 신규 지적으로 세지 않았습니다.
