# 개발 계획서 보완·금붕어 재검토 결과

- 작성일: 2026-11-13
- 대상: [고정 보관함·전체 히스토리 개발 계획](/Users/crobat/dev/tidytap/docs/CLIPBOARD_PINBOARD_ICLOUD_PLAN.md), 개정 0.2
- 확정 범위 유지: 보관함 1개, 고정 항목과 일반 히스토리 모두 같은 Apple 계정의 Mac 사이에서 동기화
- 결과: 이전 지적 7건의 문서 보완을 적용했다. 재검토에서 발견한 추가 5건도 문서에 반영했다. 제품 코드·Apple 계정·클라우드 자원은 변경하지 않았다.

## 최종 판정

재검토 후 미반영 신규 지적은 없다. 마지막 구현 준비도 재검토에서 새 Blocker/Major 누락은 나오지 않았고, 남은 낮음 등급 용어 지적은 마지막에 교체했다. 용어 교체 뒤 추가 독립 재검토를 했다고 주장하지 않는다.

0단계 읽기·조사와 결정 문서 작성에는 착수할 수 있다. 전체 본구현 즉시 실행 명세는 아직 아니며, Gate0의 실제 실행·서명·시험 연결 경계와 Gate1의 저장·정책·병합 설계를 먼저 완성해야 한다. 새 누락이 없다는 판정은 이 선결 작업을 통과했다는 뜻이 아니다.

| 구분 | 미반영 신규 항목 |
| --- | ---: |
| 차단 | 0 |
| 높음 | 0 |
| 중간 | 0 |
| 낮음 | 0 |

현재 구현 전 상태의 사용자 등급이다. EGM의 Zero-Decision 표준에서 선결 설계 미완료로 제시된 Blocker는 이미 계획된 작업으로서 해당없음으로 구분했다. ‘두 번 연속 깨끗한 라운드 수렴’이나 실제 구현·배포 통과를 선언하는 보고서가 아니다.

문서 보완 상태이며 제품 코드에 위 동작을 구현했다는 표가 아니다. 정책 제안은 사용자 확정 범위와 계속 구분한다.

총 14명이 각각 `fork_turns=none`의 새 문맥으로 실행했다. 6단계는 대상만 읽었다. 다른 단계는 URS·피드백 검증·Apple 공식 자료 사본을 제공했고, 8단계에만 이번 앞 단계 보고서를 추가했다. 수정은 단계 완료 응답 후 적용했고 변경 전후 사본·해시를 보존했다. 마지막 용어 수정은 별도 재검토하지 않았다.

## 남아 있는 선결 작업 / 해당없음

- Gate0: 실제 CloudKit 실행 주체·서명·프로파일·프로브 파일·시험 연결 범위를 결정하고 안전한 두 Mac 송수신을 확인해야 한다. 현재는 실제 연결 미확인이다.
- Gate1: 저장 스키마·API·안정된 ID·병합/삭제 인과 관계·계정별 경로/표시·이관 원자성·반입 ledger·고정 한도/순서와 미완성 사건 결과를 확정해야 한다.
- 생성 예정 Gate0/Gate1 문서가 아직 없다는 점은 계획의 시작 조건에 해당한다. 실제 작성·검증 없이 제품 코드 착수나 본구현 준비도 통과로 표시하지 않는다.

## 증거·검증 한계

[반영 기록](goldfish_review_report.md)에 기존/추가 지적과 처리를 연결했다. [실행 기록](manifest.json)에 검토자 완료 상태, 문맥 해시, 단계별 대상 사본, 최종 파일 해시와 문서 검사를 기록한다. 자식의 완료·읽기 보고는 확보했지만 개별 도구 추적과 호스트 지침 주입 제외까지 독립 검증한 것은 아니다.

변경한 것은 개발 계획서·관련 URS·리뷰 산출물이다. 제품 빌드·테스트·실제 계정/CloudKit·두 Mac·서명/공증·배포는 수행하지 않았다. 원문 링크·공백·수용/사건 ID·본문의 변경 범위를 검사했으며, 실제 수렴과 이관 안전성의 통과 증거로 대체하지 않는다.
