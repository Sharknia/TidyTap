# 9단계: 구현 준비도 검토

- 대상: 계획 구현 범위 53~141행. 앞부분은 정책·정의 확인에 사용.
- 검토자: 새 문맥의 gf09_readiness, gf09_codebase, gf09_style. 모두 완료.
- 표준 판정: 전체 본구현은 Zero-Decision Rule 미통과. 0단계 문헌·코드·계정 구성 조사는 착수 가능. 이미 계획된 정책·구조 결정과 신규 보완점을 구분한다.

## 구현 준비도 검토 원시 결과

### R01: 실행 가능한 파일 변경 경계 부족

- 검토자: gf09_readiness
- EGM: Major / 사용자: 중간
- 대상: 91~100행
- 일부 경로는 첫 파일만 완전하며 서명·스크립트·테스트·문서는 영역명이다. 새 파일 이름도 후속 결정이다. 실행자가 수정 파일·시험 배치를 정해야 한다.
- 보완: 0단계 산출물에 정확한 저장소 상대경로와 단계별 생성·수정·삭제 목록을 추가한다. 1~5단계의 쓰기 경계를 확정할 수 있어야 한다.

### R02: 본구현에 앞선 설계 결정 미완료

- 검토자: gf09_readiness
- EGM: Blocker / 사용자: 해당없음, 이미 계획된 선결 작업
- 대상: 59~61·66~70·78~79·100·128~131행
- 항목 ID·동일성, 삭제와 새 동작의 순서, 저장 포맷·대기열, 실행 주체, 고정 한도·순서·계정 표시 정책을 정해야 한다. 표준상 독립 설계 결정이 남아 있어 본구현 준비도는 미통과다.
- 이 결정들은 0·1단계에 이미 명시되어 있으므로 새 누락으로 집계하지 않는다. 기술 조사·정책 정리는 착수 가능하고, 결정 결과를 기록한 뒤 해당 본구현으로 넘어가야 한다. 실제 CloudKit 연결 가능성은 미확인이다.

### R03: 구·신 버전 공존과 되돌리기 계약 누락

- 검토자: gf09_readiness
- EGM: Major / 사용자: 중간
- 대상: 62·69·79·96·115행
- 백업·이관 재시도는 있지만, 구 Helper가 살아 있을 때 새 형식에 쓰지 못하게 하는 방법과 저장소 전환 시점·다운그레이드 동작이 없다. 현재 Store는 해독하지 못한 `.clip`을 삭제하므로 같은 경로·확장자에 새 포맷을 쓰는 선택을 검증해야 한다. 실제 손상은 미확인이다.
- 보완: 저장소 버전 경계, 기존 writer 종료 확인, 전환 실패 복구와 이전 버전 실행 시의 동작을 정의한다. 1단계 이관과 5단계 업데이트 수용 기준에 추가한다.

### R04: 사건별 기대값과 단계별 검증 경계 부족

- 검토자: gf09_readiness
- EGM: Major / 사용자: 중간
- 대상: 78~83·97·110~115·120행
- ‘정책대로’, ‘정한 동작’이라는 시나리오를 입력 사건 순서와 최종 상태로 구체화해야 한다. 각 단계가 안정적인 빌드·시험 상태를 남기는 검증 경계도 부족하다.
- 보완: 재전송, 동시 고정/해제, 삭제 후 오래된 변경, 전체 삭제와 오프라인 새 복사, 이관 중 종료에 사건표·기대 항목 수·고정/삭제 상태를 적고 시험 경로·필수 검사에 연결한다.

## 코드 대조 검토 원시 결과

### K01: 본문 비기록 요구와 기존 진단 경로의 연결 누락

- 검토자: gf09_codebase
- EGM: Major / 사용자: 중간
- 대상: 100행, 변경 범위 92~93행
- 현재 `AppDelegate.swift`의 `logPendingClipboardSelection`은 검색어 앞 120자와 선택 텍스트 앞 160자를 기록한다. `TidyTapProduct.swift`의 `TidyTapClipboardPasteLog`에도 본문 미리보기 저장이 명시되며 실제 로그 경로는 계정별 기록 저장소 밖이다.
- 이 경로를 그대로 쓰면 동기화로 수신한 텍스트도 사용 시 로그에 남을 수 있다. 신규 동기화 데이터의 실제 노출은 아직 발생했다고 확인하지 않았다.
- 보완: 두 파일의 검색어·본문 미리보기 기록 변경, 기존 로그 처리, 로그에 본문이 남지 않는 시험을 작업 목록과 수용 기준에 포함한다. 실제 사용자 로그를 읽을 필요는 없다.

### K02: 실행 가능한 파일 변경 목록 부족

- 검토자: gf09_codebase
- EGM: Major / 사용자: 중간
- 대상: 89~100행
- R01과 중복. 실제 Xcode의 Helper tool target과 `Scripts/verify-release-artifact.sh`의 plain Helper 계약까지 변경 경계를 확정해야 한다. 기존 연결점은 대체로 존재하며 새 파일 부재를 개별 결함으로 집계하지 않는다.
- 보완: 0단계에서 실행 주체를 선택한 뒤 정확한 변경 경로·작업·시험을 고정하고 새 저장소·이관·동기화 파일의 생성/수정/삭제 목록을 작성한다.

## 표현·판정 기준 검토 원시 결과

### U01: ‘영구 대기 없음’의 판정 불가능

- 검토자: gf09_style
- EGM: Major / 사용자: 중간
- 대상: 112행, AC-S07
- 유한한 시험으로 ‘영구 대기 없음’을 증명할 수 없으며 Apple 문서도 자동 동기화 일정을 불확정으로 설명한다.
- 보완: CALIBRATE. 재연결·재시작 시 변경이 보존되고 실제 송수신으로 해소되는지 확인한다. 미해소 항목은 대기 사유·관찰 결과를 기록한다. 고정 완료 시간을 새로 약속하라는 뜻은 아니다.

### U02: 실제 계정 시험의 필수 범위 불명확

- 검토자: gf09_style
- EGM: Nit / 사용자: 낮음
- 대상: 113행, AC-S08
- ‘가능한 실제 계정 흐름’으로는 실제 계정 전환을 생략한 후보가 통과할 수 있는지 알 수 없다. 미실행 표기 규칙만으로 필수 시험 범위가 정해지지 않는다.
- 보완: 실제 계정 시험과 상태 주입으로 확인할 흐름을 구분하고, 실제 시험이 미실행인 경우의 AC 판정 규칙을 명시한다.
