# 설정 스크롤 겹침 수정 · 클립보드 이미지 필터 작업계획

- 작성일: 2026-09-30
- 기준 코드: `6a0006b` — 조사 시작 시 detached HEAD였으며 변경사항 없음. 구현 브랜치는 `codex/settings-scroll-image-filter`.
- 상태: 구현 및 앱 테스트 165개·격리 실행 검사 통과. Astra 적대적 리뷰 완료, 확정한 버그·회귀 없음. 실제 UI 검증의 남은 범위는 아래 기록 참조.
- 리뷰 반영: 2026-09-30 Astra 리뷰의 용량 초과 보호와 필터 전환 초점·한글 조합 보완을 관련 코드 확인 후 반영.
- 요청 범위: 설정 화면을 아래로 스크롤할 때 상단이 겹치는 문제 수정, 클립보드 히스토리에서 이미지만 보는 간단 필터.

## 1. 확인한 현황

### 설정 창의 겹침

첨부 화면에서는 창 왼쪽 위의 닫기·최소화 버튼과 TidyTap 앱 아이콘이 겹친다. 코드에서 앱 이름·아이콘 헤더가 고정 헤더로 구현된 것은 아니다. 헤더와 모든 설정 항목이 하나의 스크롤 문서에 들어 있다.

- [AppDelegate.swift](../Sources/App/AppDelegate.swift)의 `startSettingsSession()`은 설정 창에 `.fullSizeContentView`와 투명 제목 표시줄을 적용한다.
- [SettingsViewController.swift](../Sources/App/SettingsViewController.swift)의 `loadView()`는 스크롤 뷰의 상단을 루트 뷰 상단에 붙인다. 제목 표시줄 아래의 콘텐츠 영역을 기준으로 제한하지 않는다.
- `contentStack`의 상단 44pt 여백은 문서와 함께 스크롤된다. 따라서 처음 열었을 때의 여백이 창 버튼 영역을 계속 보호하지 않는다.

**원인 후보:** 스크롤 콘텐츠가 창 버튼이 있는 제목 표시줄 영역까지 올라가는 구조. 첨부 증상과 코드가 일치하지만, 현재 빌드의 실제 창에서 같은 스크롤 위치를 재현한 것은 아니다. 카드 재질 자체의 문제로 확정하지 않는다.

Apple은 `.fullSizeContentView`가 콘텐츠를 창 전체로 확장하며, 제목 표시줄 아래에 배치할 때 `contentLayoutRect` 또는 `contentLayoutGuide`를 사용하도록 안내한다. [공식 문서](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/fullsizecontentview).

### 클립보드 히스토리

- [ClipboardHistoryPanelController.swift](../Sources/App/ClipboardHistoryPanelController.swift)는 검색창, 왼쪽 목록, 오른쪽 텍스트/이미지 미리보기, 하단 붙여넣기 안내를 이미 제공한다. 기본 크기는 800pt 너비이고 작은 화면에서는 480pt까지 줄어든다.
- [ClipboardCapturedContent](../Packages/TidyTapInputEngine/Sources/TidyTapInputEngine/ClipboardPasteboardReader.swift)는 `.text`와 `.image`를 구분한다. 이미지 식별을 위한 새 데이터나 저장 형식은 필요 없다.
- 검색어가 비어 있으면 텍스트와 이미지를 모두 표시한다. 검색어가 있으면 텍스트만 검색하므로 이미지는 결과에서 빠진다.
- 큰 텍스트 검색은 백그라운드 작업과 세대 번호로 오래된 결과를 버린다. 열기, 새 복사 반영, 삭제, 검색 변경이 모두 `applyFilter()`로 모인다.
- 새 복사는 현재 선택 ID를 보존하고, 삭제 후에는 표시 목록의 행 번호로 다음 선택을 정한다. 붙여넣기는 선택 항목 ID로 기존 AppDelegate/Helper 경로를 사용한다.
- 최신 복사가 용량 제한을 넘으면 이전 항목을 자동 선택하지 않는 보호 동작이 있다.

[기존 패널 재설계 계획](CLIPBOARD_HISTORY_PANEL_REDESIGN_PLAN.md)은 당시 범위에서 유형 필터를 제외했다. 이번 요청은 그 제외 항목에 대한 후속 범위다. 기존 계획의 제외 문구를 이번 요청의 제한으로 적용하지 않는다.

## 2. 권장 구현

### A. 설정 창: 기본 제목 표시줄과 스크롤 영역 분리

1. 실제 설정 창에서 초기 위치, 중간, 맨 아래, 위쪽 탄성 스크롤을 확인해 첨부 증상을 재현한다.
2. **최소 변경안:** 설정 창의 `.fullSizeContentView`를 제거해 AppKit이 콘텐츠 영역을 제목 표시줄 아래로 나누게 한다. 창 버튼·앱 헤더·기존 설정 카드와 스크롤은 유지한다.
3. 제목 표시줄 영역이 따로 생긴 만큼 문서의 기존 44pt 상단 여백을 실제 화면 기준으로 조정한다. 여백 추가만으로 겹침을 해결하지 않는다.
4. 창 크기는 기존 `contentSizeThatFitsVisibleFrame(for:)`가 실제 창 프레임과 콘텐츠 크기 차이를 계산하므로 그 경로를 재사용한다. 작은 화면에서 일반 설정까지 도달하는지 확인한다.

베스트 프랙티스: 창 장식과 콘텐츠의 경계는 AppKit 기본 레이아웃에 맡긴다. 고정 헤더·스크롤 감지·별도 덮개를 추가할 필요가 없다.

투명 제목 표시줄까지 이어지는 배경을 반드시 유지해야 하는 시각적 요구가 확인되면, `.fullSizeContentView`를 유지하고 스크롤 영역을 `contentLayoutGuide` 아래로 제한하는 대안을 사용한다. 이 대안은 창과 컨트롤러 사이의 레이아웃 연결이 추가된다. 두 방식을 동시에 적용하지 않는다.

### B. 히스토리: `전체 / 이미지` 두 가지 필터

검색창 오른쪽에 AppKit 기본 `NSSegmentedControl`을 둔다. 텍스트 전용 탭, 필터 메뉴, 새 설정 항목은 추가하지 않는다.

| 상황 | 동작 |
| --- | --- |
| 패널 열기·다시 열기 | `전체`, 빈 검색어, 기존 검색창 초기 초점. 필터를 설정에 저장하지 않음. |
| `전체` | 기존 동작 유지. 빈 검색어는 모든 기록, 입력한 검색어는 텍스트 부분 검색. |
| `이미지` | 저장된 `.image` 기록만 최신순으로 표시. PNG/TIFF 등 저장된 이미지 타입을 모두 포함. |
| 검색 중 `이미지`로 전환 | AppKit의 검색 편집 종료 절차로 한글 조합을 처리하고 확정된 검색어를 보관. 검색 입력을 비활성화하고 초점은 필터 컨트롤로 이동. 진행 중 검색 취소 및 세대 갱신 후 즉시 이미지 목록 표시. 보관된 검색어는 적용하지 않음. |
| `전체`로 복귀 | 검색 입력을 활성화하고 보관한 검색어를 다시 적용한 뒤 검색창에 초점을 복원해 바로 입력할 수 있게 함. |
| 필터 변경 후 선택 | 기존 선택 ID가 결과에 있으면 유지. 없으면 첫 결과를 선택하되, 최신 복사 용량 초과 보호가 적용되는 상태에서는 선택 해제. `.id` 복구에서도 첫 행으로 무조건 대체하지 않음. |
| 이미지 없음 | `저장된 이미지가 없습니다` 표시. 선택·미리보기·삭제 해제, Enter로 붙여넣지 않음. 기록 전체가 비어 있거나 용량 초과인 상태는 기존 안내를 우선함. |
| 패널이 열린 채 새 복사 | 현재 필터 유지. 텍스트 복사는 이미지 목록에 나오지 않고, 이미지 복사는 목록에 반영. 기존 선택을 빼앗지 않음. |
| 이미지 삭제 | 현재 필터에서 다음 유효 행 선택. 마지막 이미지를 지우면 이미지 없음 상태. |

베스트 프랙티스: 이미 저장된 콘텐츠 타입으로 화면의 목록만 제한한다. 이미지 OCR·파일명 검색·새 검색 인덱스는 이번 요구에 필요 없다. 이미지에서 텍스트 검색을 비활성화하는 이유는 기존 검색이 이미지 내용을 검색하지 않기 때문이다.

구현 시 모든 진입점을 기존 `applyFilter()`에 모으고 이미지 분기를 그 함수 안에 둔다. 필터 전환도 기존 검색 작업 취소·세대 번호 처리를 거쳐야 한다. 목록 선택, 미리보기, 삭제, 붙여넣기는 기존 경로를 재사용한다. 이미지 모드에서 붙여넣기 진단의 `searchQuery`는 적용하지 않은 텍스트 검색어 대신 빈 값으로 제공한다.

**용량 초과 보호의 판단 기준:** 보관된 검색창 원문과 실제 적용하는 유효 검색어를 구분한다. `전체`의 유효 검색어는 공백을 정리한 검색창 값이고, `이미지`에서는 항상 빈 문자열이다. `defaultSearchSelection()`과 `updatePreview()`의 용량 초과 안내는 동일한 유효 검색어를 기준으로 판단한다. 따라서 최신 복사가 용량을 초과한 상태에서 텍스트 검색 결과를 선택했다가 이미지로 전환하면, 기존 선택 ID가 이미지 결과에 없으므로 선택을 해제하고 용량 초과 안내를 표시한다. 사용자가 목록을 클릭하거나 방향키로 항목을 명시적으로 선택한 뒤에만 해당 항목을 붙여넣을 수 있다. 이 판단은 컨트롤러 안의 작은 공통 계산으로 처리하며 별도 상태 관리 계층은 만들지 않는다.

**초점과 입력 계약:** 이미지 전환 후 비활성 검색창의 field editor가 first responder로 남지 않게 하고, 전체 복귀 시 `panel.makeFirstResponder(searchField)`로 검색 초점을 복원한다. 편집 종료·조합 확정·필터 활성화에 사용한 키를 붙여넣기로 처리하지 않는다. 전환 시 기존 `pasteKeyState`의 대기 상태도 초기화해 전환 전에 누른 Enter의 key-up이 이미지 붙여넣기로 이어지지 않게 한다. 전환이 끝난 뒤 새로 누른 Enter/Shift+Enter는 기존 붙여넣기 동작을 따른다. 한글 조합 종료는 AppKit 기본 편집 절차를 사용하고 별도 조합 파서를 만들지 않는다.

필터는 키보드와 VoiceOver로도 선택할 수 있게 레이블을 제공한다. 480pt 너비에서도 검색창·필터·포커스 링이 겹치지 않아야 한다. 필터 전환으로 패널 크기를 바꾸지 않는다.

## 4. 작업 순서와 검증

1. **재현 및 기준 확보:** 제목 표시줄이 있는 실제 설정 창에서 스크롤 전/후를 기록한다. 기존 `SettingsSnapshotRenderer`는 borderless 창을 사용하므로 그 스냅샷만으로 창 버튼 겹침을 검증하지 않는다. 기록 목록은 합성 텍스트·이미지와 임시 저장소를 사용한다.
2. **설정 수정:** 기본 창 레이아웃으로 영역을 분리하고 위·중간·아래 스크롤, 탄성 스크롤, 작은 화면의 일반 설정 도달을 확인한다. 실제 제목 표시줄이 있는 테스트 창에서 스크롤 뷰의 프레임이 `contentLayoutRect`를 넘지 않는지 검사한다.
3. **필터 구현:** 전체/이미지 전환과 유효 검색어·검색 초점의 관계부터 적용한 뒤 선택 유지·삭제·빈 상태·재호출 초기화를 연결한다. 긴 검색 도중 이미지 필터로 바꾸어 오래된 검색 결과가 이미지 목록을 덮지 않는지 확인한다.
4. **자동 검증:** 기존 앱 테스트에 최소 회귀 사례를 추가한다. 혼합 기록의 타입·순서, 검색 전환, 검색 작업 경합, 새 복사 선택 보존, 마지막 이미지 삭제를 확인한다. 용량 초과는 `용량 초과 → 텍스트 검색 → 검색 결과 선택 → 이미지 전환`을 재현해, 보관된 검색어가 있어도 선택이 해제되고 용량 초과 안내가 표시되며 Enter로 붙여넣지 않는지 검사한다. 이후 명시적인 이미지 선택으로 정상 동작하는지도 확인한다. 필터 전환의 first responder, 전체 복귀의 검색 초점 복원, 전환 전 Enter 대기 상태 초기화도 검증한다. 앱 테스트 명령은 아래와 같다.

   ```sh
   xcodebuild -project TidyTap.xcodeproj -scheme TidyTap \
     -configuration Debug CODE_SIGNING_ALLOWED=NO test
   ```

   AppDelegate의 창 구성을 변경하므로 기존 `Scripts/launch-smoke.sh`도 실행한다. 입력 엔진을 수정하지 않는 한 새 엔진 테스트는 만들지 않는다.
5. **실제 흐름 확인:** 격리 실행에서 스크롤 겹침과 필터 배치를 캡처한다. 한국어·영어, 밝은·어두운 외관, 좁은 패널, 키보드 필터 선택, 방향키, Enter/Shift+Enter, 두 번 클릭, Esc, 다시 열기를 확인한다. 한글 조합 중 이미지 필터로 전환해 검색 편집이 종료되고 의도하지 않은 붙여넣기가 없는지, 전체 복귀 후 보관된 검색어에서 바로 입력 가능한지 확인한다. 이미지 필터에서 고른 이미지가 대상 입력칸에 정확히 한 번 삽입되는지 별도로 검증한다.

## 5. 완료 기준과 현재 경계

- 설정 화면을 어느 위치로 스크롤해도 창 버튼과 앱 헤더·설정 내용이 겹치지 않는다. 아래의 일반 설정까지 접근 가능하다.
- 이미지 필터에는 이미지 기록만 최신순으로 표시되고 선택·미리보기·삭제·붙여넣기가 같은 항목을 가리킨다.
- 필터 전환 후 오래된 비동기 검색 결과가 끼어들지 않는다. 빈 결과·용량 초과에서는 선택 없는 Enter가 다른 기록을 붙여넣지 않는다.
- 보관된 텍스트 검색어가 이미지 모드의 용량 초과 보호를 해제하지 않는다. 한글 조합·필터 전환 자체로 붙여넣기가 발생하지 않고, 전체 복귀 후 바로 검색 입력이 가능하다.
- 패널을 다시 열면 전체 목록과 검색 초기 초점을 얻는다. 필터를 조작하거나 목록을 보는 것만으로 클립보드가 바뀌지 않는다.
- 자동 테스트 통과와 실제 창·입력칸 검증을 나누어 기록한다. 실제 삽입을 확인하지 못하면 미검증으로 남긴다.
- 사용자의 후속 구현 요청에 따라 전용 브랜치에 단계별 커밋·푸시했다. 이후 별도 요청에 따라 0.2.3 빌드 9를 서명·공증해 로컬에 설치했다. 공개 릴리스와 업데이트 피드는 변경하지 않았다.

### Astra 적대적 리뷰

`6a0006b..2f07203`을 읽기 전용으로 검토했으며, 확정할 P1/P2/P3 버그·회귀는 발견되지 않았다. 검색 취소·세대 검증, 선택 ID와 용량 초과 보호, 삭제 후 필터 내 선택, 재호출 초기화를 확인했다. 별도 AppKit 합성 프로브에서는 조합 문자열이 `endEditing` 후 보존됐고, 필터 선택은 방향키 후 Space로 실행되며 Return은 선택키가 아니었다. 이는 실제 사용자의 한글 IME·키보드·VoiceOver 시험을 대체하지 않는다.

리뷰에서 확인한 테스트 경계: 필터 테스트 대부분은 컨트롤의 선택값과 action을 직접 호출한다. 설정 스크롤 경계 테스트는 AppDelegate의 창 스타일을 테스트 창에 복제하므로 향후 AppDelegate의 창 구성 변경을 직접 잡지는 못한다. 실제 설정 창은 격리 실행 검사로 별도 확인했지만, 탄성 스크롤의 시각 검증과 실제 Helper를 통한 외부 앱 삽입은 남아 있다.


### 후속 로컬 설치

사용자가 버전 0.2.3을 지정하고 로컬 설치를 요청했다. 소스 커밋 `1adcece`의 서명·공증 DMG로 `/Applications/TidyTap.app`을 교체했고, 앱·Helper 실행과 설정·권한 응답을 확인했다. 상세 산출물과 검증은 [0.2.3 로컬 설치 기록](RELEASE_NOTES_0.2.3.md)을 참고한다. 기존 실제 사용 검증의 남은 항목을 전체 통과로 변경하지 않는다.
