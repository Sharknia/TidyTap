# 클립보드 히스토리 입력 초점 복귀 작업계획

- 작성일: 2026-09-29
- 상태: **구현·검증 진행 중**. 후속 요청에 따라 이 계획을 구현하고, `dev`와 `main` PR을 거쳐 0.2.2로 릴리스한다.
- 착수 당시 기준 환경: 설치된 0.2.1은 진단 로그 버전이었으며 재확인 수정본은 설치하지 않았다. 진단 로깅 변경은 미커밋 상태였다.
- 범위: 히스토리 항목을 선택한 뒤 원래 입력칸으로 돌아가는 Helper의 초점 확인과 붙여넣기 1회 실행.
- 관련 기준: [MVP 작업 계획의 G2·붙여넣기](CLIPBOARD_HISTORY_WORK_PLAN.md), [수용 현황의 AC-13](CLIPBOARD_HISTORY_ACCEPTANCE_STATUS.md).

## 확인한 사실과 판단의 경계

| 실제 실패 세션 (UTC) | 원래 입력 요소 | 복귀 직후 | 첫 추가 기록 | 선택 조건 |
| --- | --- | --- | --- | --- |
| 12:31:05, `29F7B0BD` | AX 조회 성공·요소 있음 | 대상 앱 전면, `kAXErrorNoValue(-25212)` | 로그 시각상 46ms 뒤 원래 요소와 일치 | 검색어 없음, 원본 28번째 |
| 12:40:31, `5E847F07` | AX 조회 성공·요소 있음 | 대상 앱 전면, `kAXErrorNoValue(-25212)` | 로그 시각상 47ms 뒤 원래 요소와 일치 | 검색어 없음, 원본 3번째 |

현재 [앱](../Sources/App/AppDelegate.swift)은 대상 앱의 PID가 전면에 오면 붙여넣기 요청을 보낸다. [Helper](../Sources/Helper/FinderFeedbackAppHost.swift)는 그 직후 `kAXFocusedUIElementAttribute`를 한 번 조회하고, 값 없음과 다른 입력 요소를 같은 `focusChanged` 오류로 처리한다. **앱 활성화 완료와 특정 입력 요소의 AX 값 준비 완료를 같은 조건으로 취급한 조기 실패 판정**이 두 건에서 확인된 TidyTap 쪽 문제다.

두 로그의 첫 추가 샘플은 예약 이름이 `30ms`일 뿐 실제 복구 시각의 상한을 뜻하지 않는다. 복구가 일어난 정확한 시점, macOS 접근성 계층과 대상 앱 내부 중 어느 쪽이 잠깐 값을 비웠는지는 확인하지 못했다. 검색과 비최신 항목 선택은 이 오류의 필수 조건으로 입증되지 않았다. 로그의 검색어·클립보드 미리보기는 이 문서에 옮기지 않는다.

## 변경 계약

1. Helper가 히스토리를 열 때 저장한 원래 AX 입력 요소가 없으면 기존처럼 실패한다. 추측한 대상에 붙여넣지 않는다.
2. 붙여넣기 요청에서 대상 앱이 살아 있고 전면이며, **현재 AX 조회만 `kAXErrorNoValue`**인 경우에 한해 비동기로 재확인한다. 30ms 간격, 최대 5회 추가 조회(약 150ms)를 초기 기준으로 둔다. 초점 재확인은 앱이 보낸 잠자기 중에도 흐르는 단조 시계 기준 만료 시각과 Helper의 0.5초 상한 중 이른 때에 끝내고, 최종 쓰기·키 전송은 앱의 요청 만료 시각 전에 끝낸다. Helper의 메인 루프와 이벤트 탭을 `sleep`으로 막지 않는다.
3. 매 재확인 전에 원래 대상 PID가 여전히 살아 있고 전면인지 검사한다. 현재 요소가 나타나면 저장한 원래 요소와 `CFEqual`로 일치할 때만 진행한다. 다른 요소가 나오면 즉시 실패한다. `NoValue`가 끝까지 지속되거나 권한·대상 앱 상태가 달라져도 실패한다. 다른 AX 오류를 임의로 재시도하지 않는다.
4. 확인이 끝나기 전에는 시스템 클립보드를 쓰거나 `⌘V`를 보내지 않는다. 항목을 읽고 키 이벤트를 준비한 뒤 쓰기 직전과 **쓰기 직후 키 전송 전**에 대상 앱의 전면 상태·원래 AX 요소·만료 시각을 다시 확인한다. 쓰기 중 대상이 바뀌면 키를 보내지 않는다. 한 요청에 클립보드 쓰기와 붙여넣기 키 전송은 각각 최대 한 번만 실행한다.
5. 재확인 중 새 호출이나 요청이 들어왔을 때 이전 세션이 뒤늦게 붙여넣지 않도록 Helper에서 진행 중인 세션 ID를 관리한다. 앱의 대상 활성화 대기부터 Helper 응답까지 같은 세션을 검사한다. 이전 요청은 명시적으로 완료 처리하고 **오래된 세션의 키 전송·뒤늦은 오류창**이 없도록 검증한다.
6. 현재의 사용자 전용·최대 256KiB 붙여넣기 로그는 유지한다. 실패 사유와 재확인 횟수, 재확인 후 원래 요소와의 일치 여부를 **판정 뒤에** 기록한다. 진단 기록은 입력 메인 루프에서 비동기로 분리하고, 7일 지난 기록은 다음 사용 시 제거하며 항목 삭제 시 지운다. 요청 전 파일 기록을 추가해 타이밍을 바꾸지 않는다.

이 변경은 일시적인 `NoValue`로 확인된 실패만 겨냥한다. 검색 UI, 결과 순서, 내용 저장·승격 정책, 권한 설정, 실제로 달라진 입력칸에 붙여넣지 않는 안전 경계는 확장하지 않는다. 위 변경 계약은 로컬 검증 범위이며, 후속 요청의 0.2.2 공개 릴리스는 별도 릴리스 절차를 따른다.

클립보드 쓰기 자체가 진행되는 동안 대상이 바뀌면 쓰기를 되돌릴 수 없을 수 있다. 쓰기 직후 재확인 실패 시 **붙여넣기 키는 보내지 않고**, 시스템 클립보드가 선택 항목으로 바뀐 상태일 수 있음을 검증 결과에 구분해 남긴다.

## 구현·검증 순서

1. **Helper 상태 분리:** 전면 앱 검사, 현재 AX 조회, 재확인 예약, 원래 요소 일치 판정, 클립보드 쓰기·키 전송을 구분한다. 재확인 횟수와 세션 수명을 한곳에서 관리한다. 앱의 2초 Helper 응답 타임아웃보다 충분히 짧게 완료한다.
2. **결정적 안전 시험:** 주입 가능한 AX 조회·스케줄러로 `NoValue → 원래 요소`, `NoValue 지속`, `NoValue → 다른 요소`, 원래 요소 없음, 대상 앱 종료·전환, 재확인 중 새 호출을 각각 시험한다. 성공 조건에서는 **붙여넣기 한 번**, 나머지에서는 **클립보드 변경과 키 전송 0회**를 검사한다.
3. **기존 테스트:** 앱과 입력 엔진 테스트를 실행한다. `Enter`·두 번 클릭·`Shift+Enter`·한글 조합, 취소, 이미지·서식 경로의 회귀를 확인한다. 테스트 통과를 대상 앱의 실제 삽입 증거로 대체하지 않는다.
4. **로컬 설치 후보:** Release archive/export로 앱·Helper·Sparkle 내부 코드를 같은 Developer ID로 서명하고 Apple 공증을 받는다. 티켓을 첨부한 뒤 `codesign --verify --deep --strict`, `stapler validate`, `spctl --assess`의 **Notarized Developer ID / accepted**를 확인한다. 현재 설치본을 복구 가능하게 보존하고, 지정 요구사항·기존 권한·Helper 재시작을 확인한다.
5. **실제 입력 검증:** 물리 단축키로 TextEdit 및 사용 중인 앱의 안전한 입력칸에서 검색어 없음/있음, 최신/오래된 항목, Enter/두 번 클릭을 반복한다. 텍스트와 이미지 각각 실제 삽입이 한 번인지, 검색어·Enter가 대상 앱에 새로 입력되지 않는지 확인한다. 의도적으로 다른 입력칸으로 옮기거나 대상 앱을 종료했을 때는 붙여넣기가 0회여야 한다. 로그의 재확인 횟수와 화면 결과를 같은 세션으로 대조한다.

## 완료 기준과 후속 조사 조건

- 실제로 확인된 `NoValue → 원래 요소 복귀`에서는 경고 없이 원래 입력칸에 선택 항목이 정확히 한 번 삽입된다. 클립보드 쓰기·키 전송 로그만으로 성공 처리하지 않는다.
- 다른 요소·다른 앱·종료·지속적인 `NoValue`에서는 잘못된 곳에 붙여넣지 않고 이유를 남긴다. 재확인 대기 중 새 세션이 시작돼도 이전 항목이 뒤늦게 붙지 않는다.
- 제한된 재확인 뒤에도 같은 오류가 남거나 AX 요소가 다르게 돌아오면 대기 시간을 무작정 늘리지 않는다. 그때 대상 앱의 key window·first responder 변화와 외부 AX 조회를 같은 단조 시계로 계측해 **대상 내부 초점 복귀 지연**과 **AX 제공·전달 지연**을 구분한다.
- 실제 검증 결과와 미검증 범위를 [수용 현황](CLIPBOARD_HISTORY_ACCEPTANCE_STATUS.md)에 기록한다.
