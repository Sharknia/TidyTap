# Finder 복사·이동 준비 알림

상태: 구현·자동 테스트·독립 리뷰·실제 패널 표시 검증 완료

## 사용자 계약

- 기존 Finder 잘라내기 기능이 켜져 있을 때 파일 목록의 Cmd-X/C에 적용한다.
- Cmd-X를 변환한 파일 복사의 클립보드 갱신 확인 후 ‘이동 준비됨’을 표시한다.
- 일반 Cmd-C의 파일 클립보드 갱신 확인 후 ‘복사 준비됨’을 표시한다.
- 선택한 파일 옆에 약 1초간 표시한다. 창을 활성화하거나 클릭·키 입력을 가로채지 않는다.
- 여러 파일이면 첫 번째 화면 안 선택 항목 옆에 한 번 표시한다.
- 좌표 조회 실패·선택 변경·텍스트 입력·다른 앱·파일이 아닌 클립보드는 표시하지 않는다.
- 하단/포인터 위치로 추측하여 표시하는 대체 위치는 추가하지 않는다.
- 새 설정 토글이나 시스템 알림 권한은 추가하지 않는다. 기존 복사·이동 계약은 유지한다.

## 구성

엔진은 최초 선택 위치와 파일 목록 문맥을 캡처하고, 클립보드 변경을 확인해
FinderFeedback을 전달한다. 알림 확인은 이동 기억과 구분하며 일반 C가 이동 기억을
취소하는 규칙 및 무효화된 cut pending의 전송 슬롯 유지 규칙을 바꾸지 않는다.
좌표 확인 때문에 이벤트 탭이 장시간 대기하지 않도록 AX 조회 예산을 유지한다.

선택 좌표는 [실험 기록](../Spikes/FinderSelectionFrameProbe/README.md)에 따른다.
AXPosition/AXSize는 화면 포인트 좌표다. AppKit 좌표 변환 기준은 주 디스플레이이며
전체 화면들의 최대 Y값을 기준으로 하지 않는다. 대상 화면의 visibleFrame 안으로 보정한다.
목록·계층은 파일명, 아이콘·갤러리는 선택 아이콘/썸네일 옆을 사용한다.

표시는 nonactivating NSPanel과 NSVisualEffectView(.popover)를 사용한다.
패널은 한 개를 재사용하고 새 확인이 오면 내용·위치를 교체하며 1초를 다시 센다.
타이머는 common run-loop modes에서 작동한다. macOS 15.1에서 사용할 수 있는 API만 쓴다.

## 프로세스 경계

Helper에서 NSPanel을 생성하면 NSApplication이 자동 생성된다. 임시 앱 구조의 실험에서
accessory/prohibited 정책 모두 이후 open이 Helper로 전달되어 설정 앱이 실행되지 않았다.
따라서 Helper는 기존처럼 NSApplication을 만들지 않는다.

기존 설정 App이 알림 UI를 담당한다. App이 열려 있으면 IPC로 전달한다.
닫혀 있으면 기존 App 실행 파일을 알림 전용 모드로 잠깐 실행하고 표시 후 종료한다.
그 사이 사용자가 앱을 열면 일반 설정 모드로 전환하고 자동종료를 취소한다.
Helper의 기본 입력 동작은 UI 호스트 실패와 무관하게 유지한다.
별도 상주 프로세스·daemon·추가 앱 번들·새 권한은 만들지 않는다.

## 검증 기준

- 클립보드가 바뀌지 않거나 파일이 아니면 알림 없음.
- 정상 X/C는 서로 다른 정확한 문구를 전달.
- 복사 직후 선택 변경, 새로운 복사, timeout, 기능 OFF의 오래된 알림 억제.
- 일반 C 이후 기존 cut pending이 중복 전송되지 않음.
- 좌표조회가 cut/paste lock을 오래 점유하지 않음.
- 네 보기, 다중 선택, 화면 경계, 주 화면 위 보조 화면의 좌표변환.
- 표시 중 Finder가 계속 전면/키 입력 대상이며 1초 후 패널이 사라짐.
- 설정 App이 켜진 경우/꺼진 경우, 연속 알림, 알림 도중 설정 App 열기.
- macOS 15.1 타깃 빌드, 기존 앱·엔진 테스트, 독립 새 Sol 리뷰.

이번 변경은 설치된 개발 빌드에 반영할 작업이며 공개 릴리스는 아니다.
검증 실행 결과와 남은 제약은 아래에 기록한다.


## 검증 결과

- 엔진 101개 테스트 통과. 최초 선택 identity/좌표, 별도 피드백 세대, 기존 cut pending 슬롯,
  무효화와 콜백 순서 및 deferred post 순서를 검증했다.
- 전체 앱 테스트 통과. IPC/environment payload는 clipboardChangeCount를 전달하며
  표시 직전 Finder 전면과 같은 클립보드 번호인지 다시 확인한다.
- 새 Sol 독립 리뷰에서 선택 캡처 경합, lock 안 AX 조회, 오래된 피드백, App 시작 중 수신
  유실, 다중 화면 좌표축과 타이머 모드 문제를 수정하고 재검토받았다.
- UI host는 accessory 정책을 사용한다. prohibited는 윈도 표시 정책에 맞지 않아 제외했다.
  직접 Process 실행은 Finder 전면을 잃는 것이 실측돼, NSWorkspace.OpenConfiguration의
  activates=false로 비활성 실행한다. 새로운 상주 프로세스는 없다.
- 실제 임시 파일 옆 표시 검사에서 on-screen 패널 84×26, Finder 전면 유지,
  약 1초 뒤 host 종료를 확인했다. 패널 x=2470,y=675는 선택 썸네일 오른쪽 8pt 위치였다.
- 연속 알림의 수명 재시작과 reopen 시 같은 App PID의 설정 화면 승격도 검사했다.
- macOS 15.1 타깃 빌드. 실행 검증 OS는 26.5.2다. 실제 15.1 및 여러 모니터 배치의
  패널 실표시는 아직 별도 검증 대상이다.
- Release launch-smoke의 마지막 시스템 상태 해시 검사는 실행 중인 설치 앱/사용자 설정
  변화와 검사 격리 문제로 통과하지 못했다. 이를 성공으로 집계하지 않는다.
  후속 검사는 launch-smoke 전용 preferences suite를 사용하며 사용자 상태를 임의 복원하지 않았다.

## 옵션 스위치 손잡이 표시 보완

사용자가 제공한 Caps Lock 스위치 손잡이 누락 화면에 대응해, NSSwitch action 처리 중
동기 pending 통지가 와도 즉시 isEnabled=false로 바꾸지 않고 다음 main queue 턴으로
미룬다. 먼저 완료 응답이 오면 예약된 비활성화는 취소한다. 임의 시간 지연·redraw polling이나
커스텀 스위치를 추가하지 않았다. 관련 UI 테스트 16개 및 새 Sol 독립 리뷰를 통과했다.
실제 손잡이 합성 오류 자체의 자동 재현은 하지 못했으므로 사용자 화면에서 재발 여부 확인이 필요하다.
