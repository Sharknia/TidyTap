구현별 리뷰는 대화 내역을 전달하지 않은 새 Sol로 수행한다. 리뷰 프롬프트에는 대상 경로·커밋, 읽기 전용 리뷰 요청, 파일/행 근거 요구만 전달한다. 구현자의 설명과 테스트 결과는 리뷰 프롬프트에 포함하지 않는다.

## 현재 검증 근거

- 변경 전 앱 테스트: 57개 통과.
- 엔진 담당 검증: 패키지 테스트 80개 통과, warnings-as-errors 및 앱 Debug 빌드 통과.
- 통합 워크트리에서도 엔진 테스트 80개를 warnings-as-errors로 재검증했다.
- 엔진과 설정·Worker 통합 후 앱 테스트: 64개 통과.
- UI까지 통합한 앱 테스트: 68개 통과. 한/영 × 켜짐/꺼짐 × 라이트/다크 화면 스냅샷을 생성했다. 한국어 다크 ON, 영어 라이트 OFF의 배치·텍스트를 직접 확인했다.
- `Scripts/launch-smoke.sh`: Release 빌드, 560×760 설정 창, all-off 종료, Worker 중복 방지·재시작, 고정 크기만 켠 Worker 유지, 끈 뒤 종료·크기 보존 및 실제 시스템 설정 비변경 확인 통과 (`d2f105f` 기준).
- Worker 실패 복구 및 단수 표기 수정 후 최종 앱 테스트: 70개 통과 (`5fd0008` 기준).
- 마지막 Release launch smoke: `fc295b2`에서 전체 통과. 직전 재실행에서 한 차례 시스템 상태 해시 변경 경고가 있었으나 원본 통합 해시만 있어 항목/원인은 확정하지 못했다. 다음 발생 시 구분할 수 있도록 HID·단축키·운영 설정 해시를 각각 출력하게 했으며, 실패를 무시하거나 검사 범위를 축소하지 않았다. 변경 후 재실행에서는 재현되지 않았다.

## 독립 리뷰와 재개 기록

- 사용량 제한으로 UI 담당과 세 리뷰 담당이 중단됐다가 사용자 요청으로 재개했다. 초기 중단을 리뷰 완료로 계산하지 않는다.
- 엔진: 새 Sol 리뷰에서 지적 사항 없음. 리뷰어도 엔진 80개·기존 앱 57개 테스트 통과를 확인했다.
- 설정/Worker 및 smoke 초기 리뷰: 의존 구현보다 해당 기능을 사용하는 커밋이 앞서는 순서 문제가 지적됐다. 아직 푸시하지 않은 커밋을 엔진 → 설정/Worker → UI → smoke 순서로 정리한다. 이전 순서는 `codex/wheel-step-pre-review-order`에 보존했다.
- 설정/Worker 통합 재검토에서 최초 적용 실패 시 저장된 크기가 3줄로 바뀌는 문제가 발견됐다. Terra가 `db5d7c0`에서 수정하고 최초 실패·후속 변경 실패 회귀 테스트 두 개를 추가했다. 통합 커밋은 `7d016ba`이며, 새 Sol의 수정 재리뷰에서 지적 사항 없음. 리뷰어의 해당 작업 트리 앱 테스트 66개, 엔진 테스트 80개 통과.
- 최종 smoke 재검토 (`d2f105f`): 의존 순서 문제 해결 확인, 추가 지적 사항 없음.
- UI 독립 리뷰: `1 lines` 단수 표기 문제 한 건. `5fd0008`에서 한국어/영어 단수 값을 추가하고 화면·VoiceOver 표시에 반영했다. UI 구현 내역을 받지 않은 Sol의 수정 재검토에서 추가 지적 사항 없음. Swift 구문 및 한/영 카탈로그 dry-run 컴파일 통과.
- 해시 진단 추가 (`fc295b2`): 새 Sol 리뷰에서 지적 사항 없음, 셸 구문·diff 검사 통과.

구현·자동 검증·독립 리뷰는 완료했다. 설치된 앱 교체, 배포/릴리스, 실제 물리 휠 검증은 수행하지 않았다. 아래 물리 검증과 한 차례 관찰된 시스템 해시 변화의 원인 미확정은 완료된 자동 검증과 구분한다.

앱 테스트 및 launch smoke는 격리된 설정과 가짜 입력 adapter로 실행한다. 설치된 앱 교체, 실제 이벤트 전송, 전역 스크롤 설정 변경을 하지 않는다. CGEvent setter 테스트는 메모리 안에서 만든 이벤트만 검사한다.

## 물리 입력 검증은 별도

아직 실제 휠의 빠른/느린 입력 검증은 완료하지 않았다. 구현은 Scroll Reverser와 같은 비연속 ±1 line 입력에 고정 크기를 적용한다. 더 큰 delta는 크기를 유지하며, 방향 반전이 ON이면 방향만 바꾼다. 모든 속도·장치에서 완전한 가속 제거를 주장하지 않는다.

사용자가 테스트 가능한 시점에 시작 신호를 준 후 다음 순서로 진행한다.

1. 마우스만 사용해 느리게 같은 수의 물리 단계를 위/아래로 입력한다.
2. 같은 장치로 빠르게 동일 단계 수를 입력한다. 이벤트 병합·큰 delta와 실제 이동량을 비교한다.
3. 반전/고정 크기 네 조합과 크기 1·3·10을 확인한다.
4. 내장 트랙패드, Magic Trackpad를 각각 분리해 수직·수평·모멘텀을 확인한다.

빠른 입력이 조건 밖으로 나가 일정 이동 목표를 만족하지 못하면 후속 알고리즘 검토가 필요하다. 자동 테스트 통과를 이 물리 검증의 대체 근거로 삼지 않는다.
