# 클립보드 히스토리 G2 검증 기록

- 작성일: 2026-09-23
- 상태: TextEdit 일반 텍스트·격리 PNG 실사용 통과. 서식은 미검증이며 G2 전체 통과 아님.
- 기준: [작업 계획 G2](CLIPBOARD_HISTORY_WORK_PLAN.md)

## 현재 연결된 동작

- Helper가 호출 키를 받으면 호출 직전 앱의 PID와 입력 요소를 보관하고, 앱에는 PID와 일회용 세션 ID를 전달한다. 복사 본문은 프로세스 간 알림에 싣지 않는다.
- 앱은 창을 열기 전에 해당 앱이 전면인지 확인한다. 선택 후에는 창을 닫고 원래 앱을 활성화해 세션 ID·선택 항목 ID·붙여넣기 방식을 Helper에 보낸다. Helper는 원래 앱과 입력 요소를 다시 확인한 후 선택 항목을 클립보드에 기록하고 `⌘V`를 한 번 보낸다. 앱 프로세스에 추가 AX·키 전송 권한을 요구하지 않는다.
- Helper가 오류를 반환하면 원인에 맞는 안내를 표시하고, 응답이 없으면 2초 뒤 실패로 안내한다. 실제 대상 앱에 삽입됐는지는 자동으로 단정하지 않는다.
- 설정 앱이 떠 있지 않은 히스토리 전용 앱도 Helper의 적용 결과를 듣는다. 기능 끄기·권한 상실의 현재 요청 결과가 비활성 상태라면 열린 창을 닫는다. 이전 요청의 늦은 결과는 무시하도록 요청 ID 비교를 테스트했다. 실제 권한 회수 UI 흐름은 아직 미검증이다.
- Enter·두 번 클릭은 붙여넣기, Esc·창 밖 클릭·호출 키 재입력은 취소다. 취소 경로는 시스템 클립보드를 변경하지 않는다.
- Enter는 키를 놓을 때 한 번 실행한다. 길게 누른 반복 키다운을 소비한 뒤 대상 앱을 다시 활성화하므로 반복 Enter가 채팅 전송이나 터미널 명령으로 새지 않도록 설계했다. 키 순서의 단위 테스트는 통과했으나 외부 앱 결과는 미검증이다.
- 붙여넣기용 클립보드 항목에는 TidyTap 내부 표식을 추가했다. 별도 임시 클립보드 테스트에서는 이 항목이 새 복사 이력으로 다시 수집되지 않았다.
- 검색 창에는 선택 항목 삭제를 연결했다. 설정에서는 확인 후 전체 기록만 삭제하고 현재 시스템 클립보드는 유지하도록 연결했다. 삭제 정책은 사용자 결정 전 제안 상태다.
- 현재 클립보드 항목이 10 MiB 저장 한도를 넘어 기록되지 않았으면, 다음 히스토리 열기에서 이유를 표시하고 이전 기록을 자동 선택하지 않는다. 늦게 도착한 기록 변경 알림에도 선택 해제를 유지한다. 사용자가 검색하거나 목록을 직접 선택해야 붙여넣을 수 있다. 새 정상 복사가 들어오면 일반적인 최신 항목 선택으로 돌아간다. 비표시 창·임시 보드 테스트는 통과했고 실제 활성 창은 아직 미검증이다.
- 격리 설정 통합 시험에서 기본 붙여넣기를 ‘서식 포함’으로 바꾸고 적용 상태·임시 설정에 저장되는 것은 확인했다. 실제 서식 지원 앱에 삽입된 결과는 미검증이다.

## 확인한 증거와 한계

| 확인 | 증거 | 한계 |
| --- | --- | --- |
| 일반 텍스트·서식·이미지 쓰기 | 하나의 격리 테스트에서 일반 텍스트·RTF·PNG를 순서대로 복사 → 감시·로컬 기록 → 최신 이미지 선택 또는 텍스트 검색 → 붙여넣기용 쓰기 → 비표시 macOS `NSTextView` 삽입까지 확인했다. RTF는 굵게, 일반 텍스트는 굵기 없이, PNG는 이미지 첨부로 삽입됐다. 별도 테스트에서 RTF의 색상·줄바꿈, HTML·TIFF, 자체 수집 제외도 확인 | 실제 외부 앱의 서식·이미지 삽입 결과는 미검증 |
| 목록 기본 선택·검색 | 앱 테스트가 창을 띄우지 않은 상태에서 최신 항목 기본 선택, 한글 텍스트 검색, 결과 없음과 검색 초기화를 확인 | 실제 창의 초점·방향키·마우스 조작은 미검증 |
| 선택 삭제와 화면 배치 | 앱 테스트에서 삭제 후 다음/이전 항목 선택을 확인. 비표시 창의 스냅샷에서 텍스트 아이콘·이미지 썸네일·목록·미리보기·검색·동작 안내 배치를 확인 | 실제 활성 창의 선택 강조, 전체 화면 표시와 클릭 조작은 미검증 |
| 대상 앱 복귀와 키 전송 | 처음에는 앱 프로세스의 AX·키 전송 권한 부재로 실패. Helper로 옮긴 뒤 사용자가 `⌥C → Enter`를 두 번 의도적으로 시험했고, 각 시험에서 TextEdit에 문구가 한 번씩 들어갔다고 확인. Helper 결과는 모두 `posted` | 브라우저·Terminal, 다른 입력 요소로 바뀐 경우, 두 번 클릭, 서식·이미지는 미검증 |
| 격리 실행 준비 | ad hoc 서명한 최신 시험 Helper에서 키 탭·AX·이벤트 전송 권한 확인, 시험 기록 준비 후 모든 시험 프로세스 자동 정리 | 정식 설치·설정 경로는 미검증 |
| 서식·이미지 실기기 시험 준비 | `Scripts/test-clipboard-history-gates.sh --g2-media`에서 일반 텍스트·빨간 굵은 글씨·48×48 PNG를 최신순으로 가진 격리 Helper가 시작하고 자동 정리되는 것을 확인 | TextEdit에 실제로 세 방식이 삽입되는지는 아직 미실행 |
| 반복 가능한 시험 | `Scripts/test-clipboard-history-gates.sh` 일반 실행에서 `⌥C → 창 → Enter → TextEdit` 확인 | 사용자 설정으로 켠 생산 경로와 다른 앱은 추가 시험 필요 |

자동 UI 제어에서 보낸 `⌥C`는 이번 격리 Helper의 전역 키 탭에 잡히지 않고 TextEdit에 `c`로 입력됐다. 입력은 즉시 되돌렸다. 이 방식의 키 입력은 물리 단축키 수용 시험을 대체하지 않는다. 이후 Mac 잠금으로 UI 제어가 멈춰 외부 앱 삽입 시험은 진행하지 못했다.

서식·이미지 시험용 PNG를 처음 만들 때 동적 시스템 색상을 장치 RGB 비트맵에 바로 넣어 검게 렌더링됐다. 고정 RGB 색상으로 바꾼 뒤 저장된 48×48 PNG의 주황·파랑 픽셀을 확인했다. 수정한 격리 Helper는 다시 시작했지만 240초 안에 창 호출이 관찰되지 않아 자동 종료됐다. 실제 삽입 결과는 여전히 미실행이다.

이후 물리 `⌥C`로 격리 창이 열렸고, TextEdit에 주황·파랑 이미지가 한 번 삽입된 것을 사용자가 확인했다. 최초 시도에서는 `focusChanged` 오류 안내가 나타나 입력 위치가 달라진 상태의 붙여넣기를 중단했다. 다음 시도는 Helper의 `posted` 기록과 실제 이미지 한 번 삽입이 일치했다. 서식 시험에서는 Teams에 글자가 들어왔지만 서식은 보이지 않았다. 그때 시험 항목에는 RTF만 있었고 대상 입력칸의 서식 수용 여부도 확인하지 못했으므로 TidyTap 서식 실패로 단정하지 않는다. 이후 시험 항목에 동등한 HTML 표현을 추가했고 AppKit HTML 파서에서 빨간 굵은 글씨로 읽히는 것까지 확인했으나 실제 앱 결과는 아직 미확인이다.

서식 확인용으로 새 리치 TextEdit 문서를 열어 `서식` 메뉴의 ‘일반 텍스트 만들기’ 상태를 확인했지만, 물리 키 시험 뒤 그 문서는 비어 있었다. Helper의 `posted`는 대상 앱에 키 이벤트를 보냈다는 뜻이지 이 문서의 삽입 증거가 아니다. Teams의 화면 결과를 TextEdit 접근성 상태로 판정할 수 없으며, 해당 서식 시험은 미검증으로 유지한다.

이후 격리 시험에는 Helper의 `⌥C` 수신 횟수를 남겨 창 호출·붙여넣기 결과와 대조했다. 앞선 무호출 기록만으로 사용자가 키를 누르지 않은 것인지, 키가 Helper에 도달하지 않은 것인지는 구분할 수 없었다. 기록에는 키 수신 횟수만 남기며 복사 내용은 남기지 않는다.

큰 이미지 미리보기의 별도 메모리 실험에서 난수 픽셀 1724×1174 TIFF(8,096,642바이트)를 `NSImage(data:)`로 준비하는 데 0~1ms, 300×300 출력까지 첫 회 34ms·뒤이은 두 번은 각 3ms가 걸렸다. 실제 히스토리 창의 응답시간, 다른 이미지 형식·앱·기기의 수치로 일반화하지 않는다.

큰 텍스트의 첫 실험에서는 7.2 MiB를 `NSTextView`에 전부 넣고 레이아웃하는 데 약 3.9초, 42 MiB 본문을 동기 검색하는 데 약 0.7초가 걸렸다. 미리보기만 앞 2만 글자와 생략 표시로 제한하고 원본 기록·붙여넣기는 유지했다. 1 MiB를 넘는 검색 대상은 백그라운드에서 검사하고, 입력이 바뀌면 이전 검색을 취소한다. 비표시 창 테스트에서 검색 대기 중 기존 행을 선택하지 못하고 최신 검색 결과만 적용되는 것을 확인했다. 실제 활성 창의 응답시간은 아직 측정하지 않았다.

## G2 실사용에서 확인할 사항

1. 격리된 서명 앱과 일회용 문구로 TextEdit, 브라우저 입력창, Terminal의 안전한 입력 줄을 차례로 사용한다.
2. Enter와 두 번 클릭이 각각 한 번만 붙여넣고, 선택에 쓴 Enter가 대상 앱의 전송·명령 실행으로 추가 전달되지 않는지 확인한다.
3. 히스토리를 열어 둔 동안 대상 창이나 입력 요소를 바꾸거나 대상 앱을 종료하면 클립보드 쓰기·붙여넣기가 일어나지 않는지 확인한다.
4. 서식 기본값과 반대 방식, 이미지 삽입, Finder 파일 이동 대기와의 상호작용을 확인한다.

TextEdit 일반 텍스트와 격리 PNG 삽입만 실제 대상 앱에서 확인됐다. AC-07~10·12~14의 다른 조건은 완료로 표시하지 않는다.
