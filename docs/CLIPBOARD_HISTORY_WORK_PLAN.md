# 클립보드 히스토리 MVP 작업 계획

- 작성일: 2026-09-23
- 상태: 구현 경로와 코드 테스트는 연결됐고 G1~G3는 격리 시험에서 부분 확인했다. 설치 프리뷰의 호출·검색·Esc도 사용자 확인을 받았다. 대상 앱별 실제 붙여넣기, 권한 거부·복구, macOS 15.1/27, 업데이트 설치 흐름과 공개 배포는 검증 완료가 아니다. 보관 기간·용량·끄기·동일 복사·최근 사용 순서는 확정됐고 삭제 범위 등은 결정 대기 중이다. [현재 판정](CLIPBOARD_HISTORY_ACCEPTANCE_STATUS.md)을 우선한다.
- 입력: [사용자 요구사항](CLIPBOARD_HISTORY_URS.md), [기술 타당성 검토](CLIPBOARD_HISTORY_FEASIBILITY.md)

## 목표와 진행 판단

사용자가 복사한 텍스트·이미지를 `호출 단축키 → 검색·선택 → Enter 또는 두 번 클릭 → 원래 위치에 붙여넣기`로 다시 사용할 수 있게 한다. 최초 활성화에는 단축키 입력이 필요하다. 초기 격리 시험 키는 `⌥C`였고 이후 사용자가 `⌥V`도 직접 설정했다. 최신 복사 또는 성공 응답을 받은 히스토리 붙여넣기가 맨 위에 오고 창을 열면 그 항목이 선택된다. 기본 텍스트 붙여넣기는 서식 없이 실행한다.

**이하는 2026-09-23에 수립한 단계별 계획이다.** 이후 코드는 구현됐고 일부 격리 시험도 수행했다. [타당성 검토](CLIPBOARD_HISTORY_FEASIBILITY.md)의 G1~G3과 실제 설치 앱의 전체 수용은 서로 다르다. 완료 판정은 [수용 기준 현황](CLIPBOARD_HISTORY_ACCEPTANCE_STATUS.md)을 따른다. 달력 날짜나 배포일은 근거가 없어 적지 않는다.

## 적용할 최소 구조

```text
설정 앱 ── 설정 스냅샷 ──▶ Helper ── 호출 신호 ──▶ 기존 앱의 히스토리 창
                              │                         │
                              └── 클립보드 변경 감시 ──▶ 로컬 히스토리
                                                        │
                                      선택한 항목 ───────┘ → 원래 앱에 붙여넣기
```

- [설정 모델](../Sources/Shared/TidyTapSettings.swift), [설정 적용](../Sources/App/SettingsCoordinator.swift), [Helper 적용 조정](../Sources/Helper/ApplyCoordinator.swift)의 기존 요청 ID·실제 적용 결과·실패 시 복원 경로를 사용한다. 이전 설정 파일은 새 항목이 없어도 읽혀야 한다.
- 전역 단축키는 Helper가 소유한다. 현행 Finder 키 이벤트 감시는 Finder 기능이 켜져 있을 때만 설치되므로 히스토리 호출에 의존하지 않는다. 네이티브 단축키 등록·해제 경로를 우선 검증한다. 모든 앱의 키 충돌 탐지 기능은 만들지 않는다.
- 클립보드 변경 감시와 보관은 Helper의 켜진 기간에만 수행한다. 현재 변경을 확인할 때 지원하는 내용을 별도로 저장한다. 앱 내부의 붙여넣기용 쓰기는 새 복사로 다시 기록하지 않는다.
- 목록 UI는 기존 TidyTap 앱 프로세스에서 연다. 설정 앱이 종료된 경우 [현재 Finder 피드백 호출 경로](../Sources/Helper/FinderFeedbackAppHost.swift)의 비활성 시작·준비 신호를 참고한다. 현재 [Finder 피드백 패널](../Sources/Shared/FinderFeedbackPanelController.swift)은 입력을 무시하므로 히스토리 창으로 그대로 재사용하지 않는다.
- 프로세스 사이의 호출 신호에 복사 본문을 담지 않는다. 같은 사용자 계정의 제한된 로컬 저장소에서 히스토리를 읽는다. 설정 값과 히스토리 본문을 분리하고, 저장 포맷은 결정된 데이터 정책에 맞는 가장 단순한 형식으로 정한다.
- 새 상주 앱, 시스템 확장, 동기화, 검색 인덱스 서버, 전용 데이터베이스는 확인된 필요가 생기기 전에는 추가하지 않는다.

이 구조는 계획 작성 당시 **후보**였고 현재 앱·Helper 코드에 반영됐다. 실제 호출·초점의 실기기 검증 범위는 [수용 기준 현황](CLIPBOARD_HISTORY_ACCEPTANCE_STATUS.md)을 따른다.

## 순차 작업과 통과 조건

### 0. 실제 앱 경로의 기술 실험 — 본 구현 전 관문

**작업:** 테스트 전용 데이터와 격리 설정을 사용해 현행 앱/Helper에 가장 작은 실험 경로를 만든다. 더미 항목 하나와 검색 필드만으로 호출·닫기·붙여넣기를 확인하고, 읽기 권한은 대상 OS에서 별도로 검증한다. 사용 중인 TidyTap 설정·사용자 클립보드를 시험 데이터로 사용하지 않는다.

| 관문 | 반드시 확인할 흐름 | 통과 기준 |
| --- | --- | --- |
| G1 창과 자동 초점 | 설정 앱 실행 중, `⌘Q` 종료 후, 로그인 Helper 시작 후 각각 사용자 설정 키 호출. 초기 격리 시험은 `⌥C` 사용 | 다른 설정 창이 열리지 않고 히스토리 창의 검색 필드에 클릭 없이 바로 입력할 수 있음. `Esc`·호출 키 재입력으로 닫힘. |
| G2 대상 복귀 | TextEdit, 브라우저 입력창, Terminal의 안전한 입력 줄에서 더미 문구 선택 후 Enter·두 번 클릭 | 원래 위치에 한 번 붙여넣고 창이 닫힘. Enter가 대상 앱에 추가로 전달되지 않음. 대상 앱을 바꿨거나 닫았을 때 다른 곳에 붙이지 않음. |
| G3 감시와 읽기 권한 | 테스트 텍스트·스크린샷·Finder 이미지 파일 복사, 읽기 허용·거부, 연속 복사 | 지원 내용은 기록되고 파일은 제외됨. 거부 상태에서는 수집 중단·상태 안내·반복 팝업 방지. 연속 복사의 누락 정도와 감시 비용을 기록. |

**결과물:** 관문별 환경·재현 절차·관찰 결과와 실패 기록. G1 또는 G2 실패 시 보관/UI 전체 구현을 진행하지 않고 호출·초점·대상 복귀 방식을 수정한다. G3에서 백그라운드 읽기가 지원되지 않으면 권한 안내나 제품 범위를 다시 검토한다. 컴파일 성공·로그 출력만으로 관문을 통과 처리하지 않는다.

### 1. 설정·단축키·수명 연결

**작업:** 기존 키보드 설정 영역에 기능 켜기·끄기, 최초 단축키 입력, 단축키 변경, 기본 붙여넣기 방식 선택을 더한다. Helper 수명 조건에 새 기능을 포함한다. 실제 등록 성공 후에만 기능을 켠 것으로 표시하며, 등록 실패·권한 실패·취소 시 저장 상태와 UI를 일치시킨다. 변경 실패는 기존 키를 유지하고, 기능 끄기는 등록 해제와 감시 중단을 수행한다.

**통과 기준:** URS의 UF-01·UF-05와 AC-01·02·15·16. `⌥V`와 `⌥⌘V`는 데모 키로 자동 등록하지 않는다. 예전 설정 스냅샷 로드, Helper 종료·재시작, 앱 종료 후 유지, 구버전 Helper의 낡은 성공 응답 거부를 확인한다.

### 2. 복사 감시·로컬 기록

**작업:** 클립보드의 변경 여부를 확인하고 지원 형식을 한 복사 사건의 한 항목으로 읽는다. 텍스트와 가능한 서식, 이미지 내용을 기록한다. Finder 이미지 **파일**은 제외한다. 최근 복사 또는 성공 응답을 받은 히스토리 붙여넣기가 목록 맨 위에 오도록 저장·조회한다. 정해진 만료·용량·삭제 규칙을 적용하며 실패한 저장을 정상 항목으로 보이지 않게 한다.

**통과 기준:** URS-04·06·11, DET-01~03·16, AC-03·04·10·14·18. 빠른 연속 복사는 실제 계측 결과를 남기고, 놓친 항목이 있으면 일반 복사까지 100% 수집했다고 표시하지 않는다. 앱/Helper 재시작 후 기록 유지와 보관 정책 적용을 확인한다.

### 3. 검색·미리보기 창

**작업:** 검색창, 최근 복사·성공 응답을 받은 붙여넣기 순서의 목록, 텍스트·이미지 미리보기와 빈 상태만 구현한다. 검색 결과의 첫 항목이 선택되고, 방향키·한 번 클릭으로 선택과 미리보기가 즉시 바뀐다. Enter·두 번 클릭은 붙여넣기를 실행한다. `Esc`·호출 키 재입력·창 밖 클릭은 취소한다. 대상 앱 이름과 정보 패널은 표시하지 않는다.

**통과 기준:** URS-03~06·09, UF-02·03, AC-04~07·11·12·20. 한글 검색 입력·조합, 결과 없음, 새 복사 도착 중 선택 유지, 두 모니터와 전체 화면에서 창 위치·초점 접근을 확인한다.

### 4. 붙여넣기와 서식

**작업:** 선택 항목을 현재 클립보드에 올리고, 호출 직전의 유효한 입력 위치로 복귀한 뒤 한 번 붙여넣는다. 텍스트는 기본적으로 서식 없이, 설정을 바꾸면 서식 포함을 기본으로 한다. 현재 반대 방식은 `Shift+Enter`에 연결됐으며 최종 키 배치는 제안 상태다. 이미지는 이미지로 붙여넣는다. 탐색·취소는 클립보드를 변경하지 않는다.

**통과 기준:** URS-05·07·08, UF-02·04, AC-07~10·12~14. 원래 앱이 사라졌거나 포커스가 바뀐 경우 엉뚱한 앱에 입력하지 않는다. 사용자가 고른 항목만 클립보드에 남고, 뒤이은 Enter가 채팅 전송·명령 실행에 사용되지 않는다. 실제 앱의 서식·이미지 삽입을 눈으로 확인한다.

### 5. 기존 기능 회귀·권한·배포 준비

**작업:** Caps Lock, 휠, 측면 버튼, Finder 잘라내기와 히스토리를 단독·동시 활성화해 검증한다. 읽기 권한이 없는 OS·거부·변경 상태에서 실제 활성 여부를 정직하게 표시한다. 보관 안내, 삭제 방법, 한국어·영어 문구, 사용자 문서를 확정된 정책에 맞춰 갱신한다.

**통과 기준:** URS-12, DET-11~17, AC-16~21. `swift test --package-path Packages/TidyTapInputEngine`, `xcodebuild -project TidyTap.xcodeproj -scheme TidyTap -configuration Debug CODE_SIGNING_ALLOWED=NO test`, `Scripts/launch-smoke.sh`를 변경 범위에 맞춰 실행한다. 실제 UI와 TCC 권한은 단위 테스트로 대체하지 않고, 격리된 설치 환경의 서명 앱·Helper에서 확인한다. 기존 Helper가 계속 실행 중인 상태에서 새 앱으로 교체되는 경우도 검사한다. 공개 배포는 별도 릴리스 판단으로 남긴다.

## 완료의 뜻

작업 완료는 **호출 → 최신 항목 확인·검색 → 선택 → 원래 앱에 한 번 붙여넣기**가 텍스트·이미지·서식 조건에서 실제로 동작하고, 취소·거부·저장 실패 때 클립보드와 기존 기능이 약속한 상태를 지키는 경우다. 테스트의 `Done`, 빌드 성공, 단축키 등록 성공, Helper의 붙여넣기 요청 로그만으로 완료 처리하지 않는다. 각 수용 기준의 통과·미실행·실패를 구분해 기록한다.

현재 기준별 판정과 남은 증거는 [수용 기준 현황](CLIPBOARD_HISTORY_ACCEPTANCE_STATUS.md)에 기록한다.
