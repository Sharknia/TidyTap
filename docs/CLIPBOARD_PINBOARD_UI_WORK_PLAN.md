# 최근 기록·보관함 탭과 창 내부 단축키 작업 계획

- 확장 기능의 목표 제품 버전: **0.3.0**. 문서 버전과 구분하며 출시 완료를 뜻하지 않는다.

- 작성일: 2026-11-13
- 기준 코드: `main` 8d1f219
- 상태: UI/설정 제품 코드 연결·자동 시험·단계별 검토/보완 완료. 실제 CloudKit·IME/설치본 수용은 미실행.
- 사용자 확정: 창을 열면 항상 최근 기록, 상단의 최근 기록/보관함 전환, 창 내부 전용 ⌘1/⌘2, 마우스 전환 유지. 보관함은 1개이며 여러 항목을 담는다.
- 추가 확정: OFF는 송수신 일시중지다. ON에서 OFF 중 유효한 로컬 기록/변경과 원격 기록을 합친다. Core Data 관리형 전송을 구현하고 실제 두 Mac 검증은 별도 미실행으로 남긴다.
- 상위 범위: [고정 보관함·전체 히스토리 동기화 계획](CLIPBOARD_PINBOARD_ICLOUD_PLAN.md). 이 문서는 그 계획의 2단계 UI를 구체화하며 일반 히스토리 동기화 범위를 줄이지 않는다.

## 1. 사용자 흐름과 채택 범위

최근 기록을 보려는 사용자가 고정 항목 아래로 스크롤하지 않도록, 두 목록을 같은 창의 같은 공간에 번갈아 표시한다. 창을 열자마자 검색·선택·붙여넣기를 할 수 있고, 보관함은 ⌘2 또는 마우스로 연다.

```text
[최근 기록 ⌘1] [보관함 ⌘2]
[검색…]                     [전체 / 이미지]
──────────────────────────────────────────
최근 기록 또는 고정 목록 │ 선택 항목 미리보기
                        │
──────────────────────────────────────────
붙여넣기 안내           [고정/해제] [기록 삭제]
```

| 항목 | 확정·구현 기준 |
| --- | --- |
| 창 열기 | 항상 최근 기록·전체 필터·빈 검색어. 보관함을 보다가 닫아도 다음 열기는 최근 기록 |
| 탭 표시 | 검색창 위에 `최근 기록 ⌘1`, `보관함 ⌘2`. 기존 전체/이미지 필터와 역할을 구분 |
| 목록 공간 | 기존 왼쪽 목록과 오른쪽 미리보기 재사용. 고정 항목을 최근 기록 위에 쌓지 않음 |
| 고정 | 최근 기록의 선택 항목을 하단 `보관함에 고정`으로 담음. 일반 기록에도 남아 있을 수 있음. 단순 고정으로 순서·보관 시각·클립보드는 바꾸지 않음 |
| 해제·삭제 | 고정된 선택 항목은 `고정 해제`. 최근 기록에서는 별도 `기록 삭제` 제공. 보관함에서는 기록 삭제 버튼을 숨기고 고정 해제만 제공 |
| 붙여넣기 | Enter·더블클릭, 기본 서식과 Shift+Enter 반전, 이미지, 원래 입력 위치 복귀를 유지 |
| 단축키 범위 | 이 패널이 보이고 키보드 입력을 받는 동안만 ⌘1 최근 기록, ⌘2 보관함. 전역 등록·입력 tap 변경 없음 |
| 동기화 옵션 | 설정 화면에 독립 `iCloud 동기화` 스위치. 기록 수집을 꺼도 이 옵션은 보여 끌 수 있음. 기기별 기본 꺼짐은 기준안이며 설정 자체는 다른 Mac으로 동기화하지 않음 |

같은 ID의 항목이 두 탭에 보이는 것은 각각의 목록에 속하기 때문이다. 새 복사나 원격 수신 때문에 탭이 저절로 바뀌거나 다른 창이 열려서는 안 된다.

보관함을 보려면 탭 전환이 한 번 필요하다. 창은 최근 기록으로 열고, 보관함은 ⌘2 또는 마우스로 전환한다. 통합 고정 영역은 최근 기록을 밀어내므로 채택하지 않는다. 별도 창·사이드바·여러 보관함·항목별 단축키·⌘번호 즉시 붙여넣기·단축키 충돌 자동 탐지·맞춤 단축키 설정은 이번 범위에 넣지 않는다.

## 2. 상태 전환 기준

여기서 ‘목록 원본’은 검색·이미지 필터를 적용하기 전 현재 탭의 항목 순서다. 두 탭의 순서는 저장 계층이 주며 UI가 고정 순서 정책을 새로 결정하지 않는다.

| 사건 | 결과 |
| --- | --- |
| 같은 표시 세션에서 탭 전환 | 나가는 탭의 검색어·전체/이미지 필터·선택 ID·스크롤 위치를 메모리에 보존. 들어가는 탭의 상태 복원. 첫 방문이면 빈 검색·전체 |
| 들어가는 탭의 선택 | 저장된 유효 선택 ID가 우선. 첫 방문에서 현재 선택 ID가 새 결과에도 있으면 유지. 그 외 첫 결과. 최신 복사 크기 초과의 자동 선택 금지 상태면 임의 첫 행 선택 안 함 |
| 같은 탭 재선택 | 검색·선택·필터·스크롤을 초기화하지 않는 동작 없음 처리 |
| 새 복사·원격 변경·변경 완료 | 적용 직전 현재 탭과 검색/필터·선택 ID·행·스크롤을 기준으로 갱신. 선택 ID가 결과에 남으면 유지. 사라지면 그 현재 행과 새 마지막 행 중 작은 행 선택. 다른 탭에서 요청한 과거 행 번호를 적용하지 않음. 자동 선택 금지 상태는 계속 준수 |
| 검색·필터 | 현재 탭만 대상으로 기존 부분 검색/이미지 필터 적용. 이미지에서는 검색 입력을 비활성화하고 그 탭의 확정 검색어는 보존. 전체로 돌아오면 복원 |
| 고정 성공 | 최근 기록에서 현재 선택·스크롤 유지. 보관함에 추가되지만 자동 전환하지 않음. 고정 표식·버튼 상태 갱신 |
| 보관함에서 해제 성공 | 해당 행 제거 후 인접 행 선택. 마지막 항목이면 빈 상태. 최근 기록의 유효한 항목은 삭제하지 않음 |
| 일반 기록 삭제 성공 | 최근 기록 행만 제거. 고정 상태는 유지. 보관함에서 영구 삭제하는 기능을 만들지 않음 |
| 빈 보관함 | `보관함이 비어 있습니다`, `최근 기록에서 항목을 고정하면 여기에 모입니다.`. 붙여넣기·고정/해제 비활성화 |
| 검색 결과/이미지 없음 | 기존 검색 결과 없음/이미지 없음 상태. 선택·미리보기·관련 동작 해제 |
| 닫기·붙여넣기로 창 숨기기 | 검색 작업·키 입력 상태·해당 세션의 UI 요청을 정리. 탭별 상태를 영구 저장하지 않음. 다음 열기는 초기 최근 기록 상태 |

탭 전환 시 검색 작업 세대 번호를 갱신하고 이전 작업을 취소한다. 이전 탭의 늦은 검색 결과가 현재 탭을 덮어쓰지 않는다. 새 복사가 목록 원본을 바꾼 경우 스크롤은 선택 행이 보이는 범위에서 복원한다.

## 3. 단축키·입력·실패 처리

| 입력·상태 | 처리 |
| --- | --- |
| 패널 숨김·비키 창 | 이벤트를 그대로 반환. 다른 앱/설정 창의 ⌘1/⌘2 동작에 관여하지 않음 |
| 정확한 ⌘1/⌘2 | 이 두 조합만 탭 전환. Caps Lock·숫자 키패드 사용만으로 단축키를 거부하지 않음 |
| 키 누름·반복·해제 | 최초 누름에만 전환. 반복 입력과 대응 키 해제는 추가 전환/문자 입력 없이 처리. Command를 숫자보다 먼저 놓아도 같은 결과. 닫기·붙여넣기 때 입력 상태 정리 |
| ⌘⇧1·⌘⌥2·⌃⌘1·일반 1/2 | 탭 전환으로 처리하지 않고 그대로 반환 |
| 한글 조합 중 전환 | 네이티브 편집 종료를 먼저 요청. 거부되거나 조합이 남으면 원래 탭·검색·조합을 유지하고 키를 기존 입력 처리로 돌려줌. 강제로 조합을 비우지 않음. 성공하면 확정 검색어를 보존한 뒤 전환 |
| 마우스 전환 중 편집 종료 실패 | 원래 탭 버튼 선택과 검색 내용·초점을 복구. 키 전환과 같은 상태 전환 함수를 사용 |
| 전환 뒤 초점 | 전체 필터면 검색창, 이미지 필터면 콘텐츠 필터. 검색·목록·핀 버튼도 Tab 이동 가능. 검색 조합 중 Enter는 기존처럼 확정 입력에 우선 사용 |
| 시스템/다른 도구의 전역 단축키 선점 | 이 창 내부 처리만으로 해소한다고 보장하지 않음. 마우스 탭 전환은 항상 유지. 사용자 환경에서 실제 확인 |

기존 Enter·Esc·방향키 조작은 유지한다. 단축키를 메뉴/전역/로컬에 중복 등록하지 않는다.

고정·해제·삭제는 저장이 성공한 뒤 반영하며 실패한 동작을 성공처럼 표시하지 않는다. 한 건 제한은 현재 표시 세션의 고정/해제·기록 삭제 조작에 적용한다. 요청 중에는 두 동작 버튼을 잠그고 탐색·검색·탭 전환은 유지한다. 닫고 새로 열면 새 요청을 허용한다. 저장 계층은 같은 계정에서 이미 접수한 요청을 포함해 접수 순서로 직렬 반영해야 하며 U0에서 이 계약을 확인한다. 기존 비활성 상태 안내 영역을 재사용하되 붙여넣기 오류와 보관함 변경 오류를 별도 상태로 보존한다. 둘 다 있으면 붙여넣기 안내 뒤 변경 실패 안내를 최대 두 줄로 표시하며 창 포커스를 빼앗는 경고창은 띄우지 않는다.

### 동기화 옵션·주기·충돌의 구분

켜기·끄기는 설정에서 제공하며 패널에 새 동기화 화면이나 계층을 추가하지 않는다. 끄기는 새 송수신 예약 중단과 진행 중 요청의 취소·정리 요청이다. 로컬·원격 기록을 삭제하거나 로컬 수집까지 켜고 끄는 동작이 아니다. 이미 서버가 받은 변경을 취소로 되돌린다고 약속하지 않는다. 정리가 진행 중이면 ‘끄는 중’, 정리 완료 후 ‘꺼짐’으로 표시한다. 다시 켜면 같은 계정의 OFF 중 유효한 새 복사·고정·삭제와 원격 변경을 조정한다. 삭제/만료된 항목을 단순 합집합으로 복원하지 않는다. OFF 중 새 복사를 영구 비공개로 두는 별도 참여 모드는 만들지 않는다.

주기는 관리형 Core Data의 자동 import/export 일정이다. 고정 N초 폴링과 초 단위 반영을 보장하지 않는다. 창은 로컬 기록을 즉시 보여주고 동기화 완료를 기다려 열지 않는다. Core Data fetch를 서버 강제 새로고침으로 표시하지 않는다. 설정의 재시도는 공개 API로 검증한 오류 복구/재연결로만 구현하고 OFF를 우회해 연결하지 않는다. 옵션만 nil로 바꾸면 즉시 일시중지된다고 가정하지 않으며, 같은 store/이력을 유지한 OFF 전환과 ON 재개는 상위 Gate0의 필수 시험이다.

동기화가 지연되는 동안에는 두 Mac이 서로의 변경을 받지 못한 채 같은 기록을 바꿀 수 있다. 서로 다른 새 복사 항목은 별도 기록으로 병합할 수 있지만, 같은 ID의 고정/해제·삭제/재수신·전체 삭제/오프라인 복사·만료/최근 사용 갱신은 충돌 후보가 된다. 위험과 사건은 상위 계획에서 검토했으며, 인과 관계·동시 변경의 승자·삭제 표식 보존 기간 등 최종 병합 규칙과 실제 두 Mac 검증은 아직 완료하지 않았다. 이 UI 단계가 병합 정책을 임의로 결정하거나 안전성을 입증했다고 표시하지 않는다.

## 4. 구현 계약과 의존성

### 데이터 경계

현재 `ClipboardHistoryEntry`는 고정 상태나 일반 기록 소속을 갖고 있지 않다. 관리형 후보 Gate0 통과와 Gate1의 저장/값 변환 계약이 먼저 준비돼야 실제 보관 기능을 연결할 수 있다. UI에 임시 고정 파일·별도 preferences 보관함·가짜 성공 경로를 만들지 않는다. 저장/동기화 스키마는 이 UI 계획에서 변경하지 않는다.

패널 내부에 메모리 전용 `LibrarySnapshot`을 두며 필드는 `entries: [ClipboardHistoryEntry]`, `historyOrder: [UUID]`, `pinnedOrder: [UUID]`다. 항목 본문은 하나이고 두 순서 배열로 소속·표시 순서를 전달한다. entries ID와 각 순서 배열에 중복이 없어야 하며, entries ID 집합은 두 배열의 합집합과 같아야 한다. 같은 유효 표시 세션의 갱신 입력이 잘못됐으면 현재 유효 목록을 유지하고 오류로 처리한다. 새 표시 세션은 이전 snapshot을 폐기하고 첫 입력을 검증한다. 첫 입력이 잘못됐으면 패널을 열지 않고 선택·콜백·키 상태를 비운다. 이것은 저장 포맷이 아니며 잘못된 입력의 일부만 반영하지 않는다.

`show(entries:...)`를 `show(snapshot:...) -> Bool`로, `updateEntries`·`refreshPreservingSelection`의 배열 입력도 snapshot으로 바꾼다. `refreshAfterDeleting`는 삭제하고 기존 호출자를 공통 `refreshPreservingSelection` 경로로 옮긴다. show는 유효한 입력으로 창을 열었으면 true, 첫 입력 거부로 닫힌 상태를 유지하면 false를 반환한다. AppDelegate는 false에서 붙여넣기 대상을 해제하고 기존 열기 오류 경로를 사용한다. displayID·서식 기본값·크기 초과 상태·onPaste·onCancel은 유지한다. 고정/삭제 콜백은 아래 계약으로 추가/교체한다. 모든 현재 호출자와 fixture를 함께 갱신하고, 운영 코드에 ‘모든 항목은 최근 기록이며 고정 없음’이라는 암묵적 기본값을 남기지 않는다. 기존 테스트 fixture에서는 이 상태를 명시적으로 만들어 사용한다.

`sourcePosition(for:)`은 현재 탭의 필터 전 목록 원본에서 index/count를 반환한다. ID가 없으면 기존과 같이 index -1이다. Enter·더블클릭은 snapshot의 실제 entry와 현재 서식 방식으로 기존 onPaste를 호출한다. 고정 전용 ID도 Helper의 붙여넣기 조회에서 읽을 수 있어야 하며, 이는 상위 Gate1 통합 시험의 선행 조건이다.

### 변경 콜백과 늦은 응답

`show`에 `onSetPinned` 콜백을 추가한다. 입력은 ID와 원하는 최종 Bool이며 토글 명령을 보내지 않는다. 완료 콜백은 `Result<LibrarySnapshot, Error>`를 받고 MainActor에서 호출한다. AppDelegate가 저장 계층의 멱등 set-pinned 작업을 요청하고 저장 완료 후 최신 snapshot을 다시 읽는다. 최신 조회의 결과 처리에서 MainActor 완료 콜백을 즉시 호출하며, 결과가 준비된 뒤 전달을 위해 별도 Task·await·지연 큐를 추가하지 않는다. 이는 UI 결과 전달 순서에 관한 요구이며 디스크 I/O를 MainActor에서 동기 실행하라는 요구가 아니다. 오래된 작업 시작 시점 snapshot을 반환하지 않는다. 완료는 로컬 저장 확정이며 CloudKit export 완료를 기다리지 않는다. Core Data 객체/context를 패널로 넘기지 않고 같은 논리 ID·본문·순서의 값으로 변환한다. 정확한 저장 API 연결은 상위 Gate1 산출물의 함수에 맞춰 AppDelegate 한 곳에 둔다.

화면을 열 때마다 새 표시 세션 ID를 만들고, 변경 요청에는 요청 ID를 붙인다. 닫기/붙여넣기/계정 전환으로 세션이 끝나면 늦은 완료가 다음 창의 상태·오류·버튼을 직접 바꾸지 못하게 한다. 새 세션의 변경 제한은 이전 UI 세션과 독립이며, 같은 계정의 저장 API는 접수 순서로 반영한다. AppDelegate는 표시 시점의 계정 저장 핸들에 요청을 묶어 이전 요청이 나중에 활성화된 다른 계정에 쓰지 못하게 한다. 창 닫기는 이미 접수/저장된 고정을 되돌리는 동작이 아니다. 저장 결과는 다음 열기 또는 저장 변경 알림의 최신 snapshot으로 확인한다. 외부 변경 알림도 AppDelegate에서 최신 snapshot을 읽어 전달한다. 계정 전환 시 열린 패널은 닫고 이전 계정 snapshot·탭 상태를 재사용하지 않는다.

`onDelete`는 최근 기록에서만 호출하는 `onDeleteHistory`로 바꾸고, ID와 `Result<LibrarySnapshot, Error>` 완료 콜백을 받는다. 고정 변경과 같은 MainActor·최신 snapshot·세션/요청 검사를 적용한다. 요청 당시 행을 완료 때 복원하지 않는다. 완료·외부 알림 모두 공통 갱신 직전의 현재 탭/검색/필터/선택 ID/행/스크롤을 캡처한다. 현재 선택이 결과에도 있으면 그대로 유지하고, 현재 선택이 사라진 경우에만 현재 행에서 인접 행으로 이동한다. AppDelegate는 일반 기록 소속 제거 후 반환하며 고정 본문을 보존한다. 기존 `store.delete(id)`를 전체 데이터 영구 삭제로 그대로 연결하지 않는다. 실패도 완료 콜백으로 돌려줘 버튼 잠금과 안내를 해제/갱신한다. `close`와 `paste` 양쪽의 숨김 경로가 새 콜백·요청 상태·키 상태·검색 작업을 모두 정리해야 한다.

예를 들어 최근 기록 H1 삭제를 요청한 뒤 보관함의 P2를 선택했다면, 완료 후에도 P2와 그 스크롤을 유지한다. 같은 최근 기록에서 H3를 새로 골랐다면 H3를 유지한다. 여전히 H1이 현재 선택이고 그 항목이 현재 결과에서 제거됐을 때만 갱신 직전 H1의 행에 해당하는 다음 행(끝이면 직전 행)을 선택한다. 들어오는 snapshot에 맞춰 필터링한 뒤 이 규칙을 적용하며, 비동기 검색 완료에도 해당 검색 세대의 선택 문맥을 사용한다.

### 동기화 설정 연결

동기화 의도는 기존 preferences 도메인의 별도 Bool 키 `clipboardICloudSyncEnabled`에 저장하고 누락 기본값은 false로 한다. 입력용 `TidyTapSettings` Codable snapshot에는 넣지 않는다. 기존 `TidyTapPreferencesStoring`에 `readClipboardICloudSyncEnabled() -> Bool`, `writeClipboardICloudSyncEnabled(_ enabled: Bool) throws`를 추가하고 실 store와 InMemoryPreferences를 함께 갱신한다. 이 경로는 입력 request ID·apply status·로그인 항목을 바꾸거나 입력 Helper를 실행하지 않는다. 이 값은 해당 Mac의 송수신 의도이며 clipboardHistoryEnabled와 분리한다. 옵션 변경만으로 수집·손쉬운 사용 권한·단축키 등록을 켜지 않는다.

설정 저장 실패는 이전 스위치 값과 엔진 상태를 유지하고 오류를 표시한다. 저장 성공 후 실행 주체에 적용하며, UI는 저장된 의도와 적용 중/꺼짐/계정·네트워크 대기/오류 상태를 구분한다. 진행 중 결과에는 적용 세대를 확인해 늦은 켜기 결과가 나중의 끄기를 뒤집지 못하게 한다. 재실행은 저장된 off를 읽은 뒤 실제 연결 생성 여부를 결정한다. 입력 Helper의 기존 apply 성공을 CloudKit 적용 성공으로 간주하지 않는다. 정확한 실행 주체·적용 콜백은 상위 Gate0/1의 선결 계약이고 이 계약 전에는 제품 스위치를 가짜 성공 경로로 활성화하지 않는다.

SettingsCoordinator에는 위 preferences 호출만 수행하는 `saveClipboardICloudSyncEnabled(_:) throws`와 읽기 메서드를 둔다. 동기화 스위치는 전용 delegate 이벤트 `settingsViewController(_:didChangeICloudSyncEnabled:)`로 AppDelegate에 전달하며 기존 `save(_ settings:)`를 호출하지 않는다. 별도 키 저장 성공 뒤에는 반드시 선택한 동기화 실행 주체에 의도를 전달한다. 실행 주체 적용 실패는 저장된 의도와 별도 오류이며 스위치를 저장 실패처럼 되돌리지 않는다. 실행 주체의 필요 프로세스 기동은 해당 적용 계약의 책임이다.

기존 입력 설정의 `save(_:)`는 preferences 쓰기 뒤 Helper 실행에서 throw할 수 있다. 이 입력 경로는 유지하되 그 결과를 동기화 키의 저장 결과로 해석하지 않는다. 입력용 `controller.apply(settings)`도 별도 동기화 스위치 값을 덮어쓰지 않게 하고, 동기화 의도/적용 상태는 별도 UI 갱신 경로를 사용한다. 일반 입력 저장이 성공한 뒤 Helper가 실패해도 이미 저장한 동기화 의도는 유지하며, 동기화 실행 주체에 false를 보내거나 앞선 적용을 취소하지 않는다.

### 키 명령 구현

현재 `handleKey`의 패널 표시/키 창 검사를 유지한다. 탭 명령은 `charactersIgnoringModifiers`의 `1`/`2` 및 modifier의 command/shift/control/option 부분이 command만인 경우로 판별한다. keyDown이 전환에 수락되면 keyCode를 기록해 반복 keyDown과 대응 keyUp을 소비한다. 키 해제 때 modifier가 달라도 기록으로 판별한다. 이 상태는 패널 파일의 `ClipboardPaneKeyState`에 두고 기존 `ClipboardPasteKeyState` 패턴을 따른다.

탭 명령 판별은 일괄 `hasMarkedText()` 반환보다 먼저 한다. 다른 탭으로 갈 때 `panel.makeFirstResponder(nil)`로 정상 편집 종료를 요청하고 반환값과 기존 편집기의 marked text 해소를 확인한다. 실패하면 원래 탭·검색·초점을 보존하고 원래 키 이벤트를 반환한다. 강제 `endEditing(for:)`나 `discardMarkedText`로 넘어가지 않는다. 성공하면 확정 검색어를 저장해 전환한다. 같은 탭 명령은 편집 종료 없이 동작 없음으로 소비한다. 마우스 전환 실패 시 segment를 원래 탭으로 되돌린다. 실제 전환에는 `pasteKeyState.reset()`도 적용해 이전 Enter 누름이 새 탭의 붙여넣기로 이어지지 않게 한다.

### 화면과 내부 상태

기존 `NSSegmentedControl` 패턴으로 두 탭을 만들고 콘텐츠 필터 위에 36pt 행과 8pt 간격을 더한다. 너비·좌우 목록/미리보기 비율·38pt 행·시스템 재질/글꼴을 유지한다. 기존 높이 계산에 탭 영역 44pt를 더하고 화면의 실제 가용 높이 안으로 제한한다. 목록 내용이 많아져도 창 높이가 계속 늘어나지 않으며 목록만 스크롤한다. 480pt 폭·짧은 화면·한국어/영어에서 검색·필터·하단 동작이 겹치지 않게 확인한다.

`Pane`은 history/pinned 두 값이다. 탭별 `PaneState`에는 확정 검색어·필터·선택 ID·목록 스크롤 위치만 둔다. 메모리에서만 유지하고 `show`마다 두 탭 모두 초기화한다. 새 탭 선택과 마우스 클릭은 같은 `switchPane` 경로를 사용한다. 데이터 적용은 한 경로로 모으고 기존 `applyFilter`는 현재 탭의 순서 배열로 만든 원본에만 적용한다. 비동기 검색에는 검색 세대와 표시 세션을 확인한다.

새 탭 컨트롤은 identifier `clipboard.history.scope`, 기존 콘텐츠 필터는 `clipboard.history.contentFilter`를 지정한다. 현재 시험의 `NSSegmentedControl` 첫 항목 조회는 각 identifier 조회로 바꿔 두 컨트롤을 혼동하지 않게 한다.

패널 초기화는 `init(localizationBundle: Bundle = .main)`로 바꾸고 기본 호출은 유지한다. 기존 SettingsViewCopy의 번들 조회 패턴처럼 패널 안에 `text(_ key: String) -> String`을 두어 주입 번들의 `localizedString(forKey:value:table:)`로 조회한다. 기존 `String(localized:)`의 기본 번들 의존을 탭/검색/필터/제목/동작/빈 상태/오류/접근성 이름까지 이 경로로 통일한다. 새 번역 계층이나 파일은 만들지 않는다. renderer는 기존 `localizedBundle(language:)` 결과를 패널에 직접 전달한다. 한글/영문 fixture에서 실제 탭·빈 상태·동작 문구의 기대 문자열을 검사해 서로 다른 언어가 적용됐는지 확인한다.

새 제품 파일·패키지·전역 키 설정·entitlements 변경은 이 UI 단계에서 만들지 않는다. 타입은 패널 파일 안에 두고 현행 AppKit·엔진·fixture를 재사용한다. 저장 계층·Helper·CloudKit 변경이 추가로 필요하면 상위 계획의 해당 단계에서 수행하며 UI 변경에 숨겨 넣지 않는다. 설정 화면만 그리는 현재 SnapshotRenderer에는 패널의 두 탭 합성 장면을 추가하고 실제 AppKit 렌더링인지 semantic fallback인지 구분한다.

제품 구현 단계마다 `swift test --package-path Packages/TidyTapInputEngine`와 `xcodebuild -project TidyTap.xcodeproj -scheme TidyTap -configuration Debug CODE_SIGNING_ALLOWED=NO test`를 통과한 뒤 다음 단계로 간다. 실제 계정·CloudKit 네트워크는 자동/XCTest/일반 smoke에서 사용하지 않고, 상위 계획의 가짜 전송·시험 연결 격리 계약을 따른다.

## 7. 현재 상태와 문서 연결

UI 확정 범위는 기존 1개 보관함·전체 히스토리 동기화에 추가된 사용자 결정이다. 레이아웃·상태·키/콜백·시험은 이 문서의 구현 기준이며, 상위 저장 스키마·이관·동기화 정책을 확정했다고 간주하지 않는다. 상위 계획과 충돌하면 이 문서의 확정 UI 범위를 유지하면서 저장 계약을 먼저 맞춘다.

- 해당없음: Gate0/Gate1 미완료와 실제 전역 단축키 충돌 미확인은 기존/계획된 선행 확인이다. UI 문서 작성·fixture 기반 검토를 막는 새 결함이 아니다.
- 중간·미확인: 실제 한글 편집 종료·키 창 경계·고정 전용 ID 붙여넣기는 구현/실기기 시험이 필요하다. 현재 코드나 시안만으로 통과 판정하지 않는다.

현재 UI와 설정을 제품 코드에 연결하고 자동 시험/오프스크린 렌더/단계별 금붕어 검토를 수행했다. 최신 결과는 [실행 현황](CLIPBOARD_030_EXECUTION.md)을 따른다. 실제 사용자 데이터 이관·두 Mac/서명 후보 수용·공개 배포는 수행하지 않았다.

이전 UI 버전의 검토 기록: Core Data/OFF 정책 확정 전 5단계와 허용된 재검토를 마쳤다. 마지막 재검토에서 확인한 중간 등급의 설정 저장/Helper 실패 경계와 낮음 표현 2건은 문서에 보완했지만, 그 보완 뒤 추가 독립 검토는 실행하지 않았다. 본구현 전에 최종 저장 경계의 재확인이 필요하다. [검토 보고서](reviews/clipboard-pinboard-ui-2026-11-13/consolidated_review_report.md)에 원시 지적·반영·미실행 상태를 구분했다.

## 8. 기술 근거

- [AppKit 이벤트 감시](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html): 앱 내부 이벤트 처리와 이벤트 소비 범위. 다른 전역 도구의 선점을 해소한다는 근거는 아니다.
- [정상적인 first responder 변경](https://developer.apple.com/documentation/appkit/nswindow/makefirstresponder(_:)): 기존 응답자가 편집 종료를 거부하면 false를 반환할 수 있다.
- [강제 편집 종료](https://developer.apple.com/documentation/appkit/nswindow/endediting(for:)): 강제 종료는 정상 편집 종료와 다르므로 새 탭 전환에서 조합 보존의 우회 수단으로 쓰지 않는다. 실제 한글 입력 결과는 별도 검증한다.
- [관리형 동기화](https://developer.apple.com/documentation/technotes/tn3163-understanding-the-synchronization-of-nspersistentcloudkitcontainer): 로컬 save/history와 import/export를 관리한다. [시간/삭제 제한](https://developer.apple.com/documentation/technotes/tn3164-debugging-the-synchronization-of-nspersistentcloudkitcontainer)에 따라 강제 새로고침·모든 충돌 해결을 가정하지 않는다.
