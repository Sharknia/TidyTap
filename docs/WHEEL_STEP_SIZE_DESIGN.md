# 휠 단계 크기 고정 설계안

작성일: 2026-09-06  
상태: 설계 제안, 앱 구현 전  
검토한 TidyTap: `807920dd7394442f27ff672825f87e5c776053c8`

## 1. 목적과 범위

일반 마우스 휠을 천천히 한 칸씩 돌릴 때도 지정한 크기로 스크롤한다. 사용자는 휠 방향 반전과 독립적으로 이 기능을 켜고 끄고, 단계 크기를 조절할 수 있다.

이번 요청은 기존 `MVP_PLAN.md`의 0.0.2 단계 크기 제외 범위를 확장하는 후속 설계다. 기존 MVP 문서를 이번 기능의 금지 조건으로 해석하지 않는다.

- 수직 비연속 휠 입력을 대상으로 한다.
- 기존 트랙패드/unknown 분류 및 통과 정책을 유지한다. 연속 스크롤로 보고되는 Magic Mouse와 고해상도 휠은 고정 크기 적용 대상이 아니다.
- 수평 스크롤, 스무스 스크롤, 관성 생성, 장치별 프로필은 이번 기능에 포함하지 않는다.
- macOS 전역 가속 설정을 변경하지 않고 TidyTap Worker가 받는 휠 이벤트를 변환한다.
- 앱에 표시하는 ‘줄’은 스크롤 이벤트의 논리적 줄 단위다. 모든 앱에서 실제 텍스트 N줄이나 같은 픽셀 거리로 이동한다는 보장은 하지 않는다.

## 2. UI와 기본값 제안

현재 마우스 카드 안에서 다음 순서로 배치한다. 두 번째 항목은 토글과 슬라이더를 포함한 하나의 설정 행이다.

```text
휠 방향 반전                              [켬]
트랙패드는 그대로
────────────────────────────────────────────
휠 단계 크기 고정                         [끔]
휠 한 칸마다 일정한 양으로 스크롤

한 단계 이동량       ───●────────       3줄
────────────────────────────────────────────
측면 버튼 탐색                            [켬]
Safari · Finder에서 뒤로 및 앞으로
```

- 신규 기능은 기본 OFF. 단계 크기는 기본 3줄, 범위 1–10줄, 정수 간격을 제안한다. 이 수치는 Scroll Reverser의 기본값을 복제한 것이 아니며 실제 휠 검증 후 확정한다.
- OFF 상태에서도 슬라이더와 저장된 숫자를 표시하되 편집은 비활성화한다. 다시 켜면 마지막 값을 사용한다.
- OFF를 크기 0으로 표현하지 않는다. 활성화 여부와 크기는 별도 저장한다.
- 방향 반전이 OFF여도 고정 크기는 ON으로 사용할 수 있다.
- 슬라이더 드래그 중 숫자는 즉시 갱신하고, 드래그 완료 시 기존 설정 저장/적용 경로로 한 번 보낸다. 키보드 조절은 완료된 조작마다 적용한다. 입력마다 Worker 재적용을 반복하지 않는다.
- 토글과 크기 변경의 pending/실패 상태도 기존 적용 결과에 연결한다. 실패하면 확인된 설정으로 복원한다.
- 한/영 문자열과 VoiceOver 이름·현재 값·단위를 함께 추가한다. 슬라이더는 키보드로 1줄씩 조절할 수 있어야 한다.
- 기존 창은 560×650이다. 새 행의 실제 fitting size에 맞춰 높이를 계산하고, 켜기/끄기로 창 높이가 달라지지 않게 한다. 화면 작업 영역을 넘는 경우 세로 스크롤 컨테이너로 하단 권한/일반 설정 접근을 보장한다.
- 권한 설명은 접근성 ‘휠 설정과 측면 버튼에 필요’, 입력 모니터링 ‘휠 설정에 필요’로 수정한다.

| 방향 반전 | 크기 고정 | 결과 |
|---|---|---|
| OFF | OFF | 원본 스크롤 통과 |
| ON | OFF | 기존 수직 방향 반전 |
| OFF | ON | 원래 방향으로 단계 크기 적용 |
| ON | ON | 반전한 방향으로 단계 크기 적용 |

## 3. Scroll Reverser에서 확인한 실제 동작

참고 커밋: `187bf3945b6107cd8486327c6165f32e523535a4`.

- [MouseTap.m](https://github.com/pilotmoon/Scroll-Reverser/blob/187bf3945b6107cd8486327c6165f32e523535a4/MouseTap.m#L188-L207): 크기가 양수이고, 비연속 이벤트이며, 수직 line delta가 정확히 +1 또는 -1일 때만 단계 크기를 적용한다. 절댓값이 2 이상인 이벤트에는 이 처리를 하지 않는다.
- 같은 코드에서는 고정 크기 적용 시 수직 line delta만 설정한다. 소스 주석은 line delta setter가 point/fixed delta도 내부적으로 갱신한다고 설명한다. 방향만 반전할 때는 원래 point/fixed 값을 부호 반전해 다시 설정한다.
- [PrefsWindowController.m](https://github.com/pilotmoon/Scroll-Reverser/blob/187bf3945b6107cd8486327c6165f32e523535a4/PrefsWindowController.m): 슬라이더 값을 비선형 정수 크기로 바꾸며, 별도 활성화 Bool 대신 크기 0으로 기능을 끈다.
- [공식 설명](https://pilotmoon.com/scrollreverser/): 비연속 휠이 관찰되면 슬라이더를 표시하고, 가장 왼쪽 값은 시스템 기본 동작이다.

따라서 이 코드를 그대로 적용하고 ‘모든 속도와 모든 마우스에서 가속을 완전히 제거했다’고 설명하면 안 된다. TidyTap은 UI를 항상 표시하고 별도 ON/OFF를 제공한다. 이벤트 변환은 아래 호환 동작을 출발점으로 삼고, 목표 장치의 빠른 입력까지 요구를 만족하는지 검증한다.

## 4. 엔진 설계

### 설정과 전달

`TidyTapSettings`에 다음 두 값을 추가한다.

```swift
var fixedMouseWheelStepEnabled: Bool // 기본 false
var mouseWheelStepLines: Int         // 제안 기본 3, 범위 1...10
```

현재는 synthesized Codable로 전체 스냅샷을 읽는다. 새 필드를 필수로 추가하면 예전 스냅샷 디코딩에 실패해 기존 설정까지 기본값으로 돌아갈 수 있다. 사용자 지정 `init(from:)`에서 새 필드에만 `decodeIfPresent`와 기본값을 적용한다. 기존 필드는 그대로 읽는다. 저장된 새 크기 값은 범위 내로 정규화한다.

`requiresHelper`, 앱/Worker 전달 구조체, 실제 적용 설정, 부분 적용 및 롤백 상태에도 새 값을 반영한다. 기능 OFF나 권한 회수 때도 사용자가 선택한 크기는 보존한다.

`EventTapConfiguration`에는 방향 반전, 크기 고정 ON/OFF, 크기를 전달하고 다음 파생 조건을 사용한다.

```swift
needsScrollProcessing = reverseMouseScroll || fixedMouseWheelStepEnabled
```

이 조건을 이벤트 마스크, 제스처 감시, 스크롤 처리 guard, 권한 요구, 실행 여부에 일관되게 적용한다. 현재 이 경로들은 `reverseMouseScroll`만 검사하므로 토글을 추가하는 것만으로는 독립 실행되지 않는다.

### 이벤트 변환

1. 기존 분류기로 입력을 분류한다. discrete mouse가 아니면 통과한다.
2. 수직 delta가 0이면 고정 크기를 적용하지 않는다.
3. 고정 크기가 ON이고 수직 line delta가 ±1이면, 원래 부호에 방향 반전 설정을 반영한 뒤 `부호 × 지정 크기`를 새 수직 line delta로 결정한다.
4. 이 경로는 새로운 출력 명령, 예를 들어 `setVerticalScrollStep(lines:)`로 반환한다. backend는 `.scrollWheelEventDeltaAxis1`만 설정하고 기존 point/fixed 값을 다시 쓰지 않는다.
5. 고정 크기 조건에 맞지 않으면 기존 방향 반전 설정만 적용한다. 두 기능이 모두 OFF이면 원본을 반환한다.

현재 `didInvert`와 `replaceScrollDeltas`만으로는 ‘반전 없이 크기만 변경’과 ‘line만 설정’을 구분할 수 없다. 처리 결과를 pass-through / reverse deltas / set step의 명시적 동작으로 확장한다. 기존 반전의 overflow 검사와 수평 값 보존은 유지한다.

별도 이벤트 탭이나 새 이벤트 재전송은 필요하지 않다. 기존 이벤트를 변경해 반환한다. 콜백 내부에서는 UserDefaults를 읽거나 프로세스를 실행하지 않고 적용된 메모리 설정만 사용한다.

### 반드시 확인할 경계: 빠른 휠과 여러 단계 입력

위 알고리즘은 Scroll Reverser의 단일 단계 처리와 호환되는 초안이다. `abs(lineDelta) > 1`까지 일정 이동을 보장하는 설계가 완성된 상태는 아니다.

- 지원 마우스를 천천히/빠르게 같은 수의 물리 단계만큼 돌려 line/point/fixed delta, 이벤트 수와 이동량을 비교한다.
- 지원 장치가 빠를 때도 ±1 이벤트를 단계별로 내보내면 위 방식으로 목표 동작을 확인할 수 있다.
- 여러 단계가 합쳐지거나 가속된 큰 delta가 들어오면 이 초안만으로는 요구를 만족하지 못할 수 있다. 그 경우 원래 단계 수를 얻을 수 있는 입력 근거를 추가 조사하고 알고리즘을 수정한다.
- 큰 delta에 무조건 크기를 곱하면 기존 가속을 확대할 수 있고, 무조건 부호만 취하면 합쳐진 여러 단계를 한 단계로 줄일 수 있다. 어느 쪽도 검증 없이 채택하지 않는다.
- 이 검증을 UI 구현보다 먼저 수행한다. 실패했을 때 ‘느린 입력만 보정’으로 요구를 임의 축소하거나 모든 가속을 제거했다고 표시하지 않는다.

### 권한과 생명주기

기존 휠과 같은 접근성/입력 모니터링 권한을 사용한다. 크기 고정만 ON이어도 Worker와 스크롤 이벤트 탭이 실행되어야 한다. 권한 회수 시 두 휠 기능을 실제 비활성 상태로 반영하고, 접근성만 있으면 측면 버튼은 기존 부분 적용 정책에 따라 유지한다. 권한이 복구됐다고 기능을 자동으로 다시 켜지 않는다.

모든 입력 기능이 OFF가 되면 Worker가 종료되는 기존 조건에 새 토글을 포함한다. 기능을 끌 때 전역 시스템 설정을 복원하는 절차는 필요하지 않다.

## 5. 변경 파일과 구현 순서

1. `ScrollControllerTests` 및 실제 지원 마우스 관찰로 단일/고속 단계 계약을 먼저 검증한다. 시스템 이벤트를 게시하지 않는 CGEvent 검사로 line setter의 point/fixed 변화도 확인한다.
2. `Sources/Shared/TidyTapSettings.swift`에 저장 값과 마이그레이션, 권한/생명주기 조건을 추가한다.
3. `ScrollController.swift`, `EventTapController.swift`, `CGEventTapBackend.swift`에 독립 기능 설정과 line-only 변경 명령을 추가한다.
4. `Sources/Helper/ApplyCoordinator.swift`, `InputFeatureAdapters.swift`에 전달·실제 상태·부분 적용·롤백을 연결한다.
5. `Sources/App/SettingsViewController.swift`, 설정 문구 및 `Localizable.xcstrings`에 토글/슬라이더와 한/영 문구를 추가한다. 기존 UUID 기반 적용 경로를 재사용한다.
6. 앱 설정 테스트·엔진 테스트·화면 스냅샷을 확인한 뒤 물리 장치로 기능을 검증한다. 설계 완료와 실제 장치 검증 완료를 구분한다.

## 6. 완료 조건

- 방향/크기 ON/OFF 네 조합이 각각 독립적으로 작동한다.
- 최소/기본/최대 크기, 위/아래 방향, 0 delta, 큰 delta, 수평 동시 입력의 결과가 정의한 계약과 일치한다.
- 실제 CGEvent 변환 후 고정 크기 경로에 원래 가속된 point/fixed 값이 재주입되지 않는다.
- 지원 휠에서 느리게/빠르게 같은 물리 단계 수를 입력했을 때 의도한 일정 이동을 확인한다. Safari, Finder, 현재 사용 브라우저에서 확인하되 앱 간 픽셀 거리가 같을 필요는 없다.
- 내장 트랙패드와 Magic Trackpad의 수직/수평/모멘텀을 각 장치별로 분리해 검사하고 변경이 없음을 확인한다. 물리 검사는 시작 신호 후 한 장치씩 진행한다.
- 구형 설정 스냅샷을 읽어도 기존 토글이 유지되고 새 기능만 OFF로 시작한다. OFF→ON 및 앱 재실행 후 크기가 복원된다.
- 크기 고정만 켠 Worker 유지, 설정 앱 종료 후 유지, 모든 기능 OFF 시 종료가 동작한다.
- 권한 부족/회수 및 적용 실패 시 UI와 실제 설정이 일치하고 다른 독립 기능이 유지된다.
- 한국어/영어, 라이트/다크, OFF/ON/pending에서 잘림 없이 표시되고 키보드·VoiceOver로 조절할 수 있다.
