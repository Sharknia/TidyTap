## 패널 재설계 검증 — 2026-09-28

[재설계 계획](CLIPBOARD_HISTORY_PANEL_REDESIGN_PLAN.md)의 단일 패널 구성으로 코드 화면을 갱신했다. 합성 텍스트·이미지만 사용한 [실제 AppKit 렌더링 스크린샷](images/clipboard-history-rendered-text-synthetic.png)에서 검색·목록·미리보기·하단 안내가 하나의 표면에 표시되고 선택 행이 구분된다. 너비는 800pt를 유지하며, 텍스트만 있는 짧은 기록은 260pt 이상, 이미지가 있는 기록은 열기 전에 380pt 이상의 높이를 잡는다. 창 버튼을 숨긴 제목 표시줄의 위쪽 여백을 16pt로 줄이고 검색·목록의 왼쪽 여백을 정렬했다. 검색창 경계와 숨긴 창 버튼, 스크롤 영역 투명 배경·자동 숨김, 이미지 선택·결과 없음 상태를 비표시 창 테스트로 확인했다. 전체 `xcodebuild ... CODE_SIGNING_ALLOWED=NO test`는 통과했다.

이 스크린샷은 **사용자 기록이나 설치 앱을 캡처한 것이 아니다**. 새 빌드의 물리 단축키 호출, 실제 검색 포커스 테두리, 원래 앱으로의 붙여넣기, 다른 화면·보조 기술에서의 외관은 이번 재설계 후 아직 실사용으로 재확인하지 않았다. 따라서 AC-11·AC-20을 포함해 위 표의 `부분` 판정은 유지한다.

한글·영문 URL·이모지가 섞인 긴 기록에서 [기본 글꼴](images/clipboard-history-type-system-synthetic.png), [큰 글꼴과 480pt 창](images/clipboard-history-type-large-narrow-synthetic.png)을 비교했다. 큰 글꼴에서 하단 안내가 삭제 버튼을 침범하고 좁은 창에서 목록 제목이 말줄임 없이 잘리는 문제를 발견해, 안내 문구·레이블 압축·목록 열 너비를 수정했다. 화면 경계와 열 너비를 검사하는 테스트가 통과했다. 이 수동 글꼴 확대는 macOS 접근성 설정 자체의 동작을 검증한 것은 아니다.

이 Mac에 설치된 D2 Coding으로 만든 [비교 화면](images/clipboard-history-type-d2-synthetic.png)에서는 고정폭 글꼴의 제목 잘림과 본문 밀도가 증가했다. 현재 패널은 시스템 글꼴을 유지한다. [공식 SIL OFL 1.1](https://github.com/naver/d2-coding-font/blob/master/LICENSE.md)에 따라 향후 원본 폰트를 앱에 포함해 배포한다면 저작권 표시와 라이선스를 함께 제공해야 한다. 이번 빌드에는 폰트를 포함하지 않는다.

사용자 피드백 후 [9개 기록의 밀도 화면](images/clipboard-history-rendered-dense-synthetic.png)과 [1600×900 이미지 미리보기](images/clipboard-history-rendered-large-image-synthetic.png)를 추가 확인했다. 텍스트는 작은 문서 심벌, 이미지는 식별 가능한 썸네일을 같은 행에 표시한다. 이미지를 포함한 기록의 창 높이는 **열 때 한 번** 정하며, 텍스트에서 이미지로 선택을 바꿔도 창의 너비·높이가 변하지 않는 회귀 테스트가 통과했다. 해당 가로 이미지 시험에서는 원본 비율을 유지하면서 미리보기 너비의 90% 이상을 채웠다.

설정에는 `⌥V`를 **추천 단축키**로 표시하지만 자동 등록하지 않고 현재 사용자의 설정값을 유지한다. 설치본에서 `⌥C` 호출·검색·Esc는 사용자가 정상 확인했다. 이후 붙여넣기 실패 화면이 한 번 보고됐으나, 당시 코드는 대상 앱 비활성·입력 포커스 변경을 같은 문구로 표시했고 오류 코드를 기록하지 않아 이번 한 건의 원인은 판정할 수 없다. 새 코드에서는 오류 사유를 구분해 안내하고 알림을 전면에 올리도록 바꿨다. 이 동작은 **새 설치본에서 아직 실사용 검증하지 않았다**.

## 시스템 Liquid Glass 조절 대응 — 2026-09-28

설정 화면은 macOS 26 이상에서 기본 `NSGlassEffectView(.regular)`를 사용하고, 이전 지원 OS에서는 일반 표면으로 돌아간다. 수동 틴트·테두리를 제거해 시스템 재질을 우선했다. 클립보드 패널은 외관 강제를 해제했고, Finder 피드백은 비상호작용 안내이므로 기존 시스템 `NSVisualEffectView(.popover)`를 유지한다. 현재 macOS 26.5의 AppKit 테스트에서 글래스 카드·패널 기본 외관 경로를 확인했다.

[Apple WWDC26 설명](https://developer.apple.com/videos/play/wwdc2026/102/)에 따르면 macOS 27의 Liquid Glass 투명도·틴트 슬라이더는 기본 글래스를 쓰는 앱에 재컴파일 없이 자동 반영된다. 이 Mac은 macOS 26.5.2·SDK 26.5이므로 **27의 슬라이더 실제 반응은 아직 검증하지 못했다**. 앱 안의 별도 조절 슬라이더는 만들지 않았다.
